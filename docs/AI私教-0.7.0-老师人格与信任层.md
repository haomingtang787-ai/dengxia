# 灯下 0.7.0 设计草案：老师人格、教学技能、界面减法与信任层

> 状态：设计评审稿，不含代码改动。  
> 版本关系：0.6.1 作为“信任层”先交付；0.7.0 在它之上做“老师”。  
> 目标：让灯下从“讲义工具”变成一位会因你而变、只在这台电脑上记得你的本地老师。

## 0. 一句话结论

**一段人格提示词不是产品。**

真正的“独家老师”由五层组成：

1. **人格基座**：她怎么说话、什么算教好、什么不做；
2. **学生档案**：你的目标、基础、偏好和易错点；
3. **教学技能与工具**：诊断、讲解、追问、测验、错因、复习；需要时还能调用查找、总结、大纲、题测、记忆、手记、卡片；
4. **老师手记**：每节课后留下有证据的观察；
5. **可信数据层**：备份、恢复、高亮、搜索、预算都不会把记忆弄丢。

其中第 5 层就是原本 0.6.1 的规划。它不是另一条产品线，而是 0.7.0 的地基。**老师可以记错，但不能因为一次恢复失败就把你划过的重点全丢掉。**

## 1. 当前基线

0.6.0 已经具备：

- 本地文稿、页面、块、原文与解析结果；
- `habits` 表：学生称呼、讲透/适中/抓考点、先比方/先定义/先提问、一次 15/25/40 分钟、避免公式堆/长段落/没例子；
- `habitBrief`：现有提示词已经在规定字数、人称、称呼上限和例子要求；
- `study_sessions` / `study_units` / `study_messages`：一门课、逐句讲稿、多轮追问、学习总结；
- 到期卡片、手动卡、错题五箱、划词高亮、全文搜索、KaTeX、AI 预算；
- schema 10，本机真实库 7 份文稿、193 页、5 张旧卡。

缺的不是“再写一段角色设定”，而是：

- 没有稳定的人格基座，当前 `PLAN_SYSTEM` / `CHAT_SYSTEM` 只是任务说明；
- 没有学生档案，`habits` 只覆盖讲课偏好，不知道你的目标、基础和长期卡点；
- 没有跨会话记忆，每门课结束就断片；
- 没有教学技能层，模型只能“回答”，不能选择“先诊断”还是“先讲例子”；
- 没有老师工具层，总结、题测、大纲、查找、记忆分散在不同栏和按钮里，老师不能按一句自然语言统一调用；
- 没有“老师手记”，学习总结是一次性的，不会变成下一次教学的依据；
- 0.6.1 发现的可靠性问题，会让“记忆”本身不可信。

## 2. 设计原则

1. **老师不是聊天机器人。** 成功标准不是“回答完”，而是“学生能自己讲出来”。
2. **人格稳定，学生模型变化。** 老师的人格不因一次对话漂移；她对你的判断可以更新。
3. **证据优先于感觉。** 记“他在第 3 讲把特征值和特征向量混了”，不记“他基础差”。
4. **记忆可见、可改、可删。** 用户能看到老师为什么这么判断，也能一键纠正。
5. **本地优先，不做情感依赖。** 不假装真人，不玩“只有我懂你”；独家来自本地长期记忆，不来自情绪绑定。
6. **技能优先于形容词。** “耐心、严谨”要落成“先问三个问题、一次只问一个、错了追因”。
7. **默认直接，按需引导。** 用户赶时间时要能直接给答案；“带我学”是显式选择，不是强制流程。
8. **不为人格牺牲可信度。** 0.6.1 的备份、恢复、高亮和预算必须先过。
9. **能力归老师，界面做减法。** 总结、题测、大纲、查找、记忆首先是老师能调用的动作，不是一排按钮或一排新页面；界面只保留高频、可恢复、需要用户确认的入口。
10. **一屏一件事。** 不新增顶部大 tab；老师页常驻动作不超过 3 个，其余收进“更多”或直接用自然语言触发；低频能力不配独立页面。

## 3. 总体架构

```text
0.6.1 信任层（先发）
  ├─ 备份校验 / 恢复预检 / 失败回滚
  ├─ 文稿删除 / 高亮失效 / 搜索范围 / 预算兜底
  ├─ 1366×768、高 DPI、长提示条回归
  └─ CDP 隔离副本 E2E：危险路径真实点击

0.7.0 老师层
  ├─ 人格基座（稳定）
  ├─ 学生档案（目标 / 基础 / 偏好）
  ├─ 老师工具层（查找 / 总结 / 大纲 / 题测 / 记忆 / 读原文 / 卡片 / 手记）
  ├─ 教学技能路由（诊断 / 讲解 / 追问 / 测验 / 错因 / 复习 / 复述）
  ├─ 老师手记（每节课后的证据）
  └─ 长期记忆（概念 / 误解 / 有效策略）
        │
        └─ 提示词编排：人格 + 习惯 + 学生档案 + 相关记忆 + 当前课 + 技能
```

工具和技能分开：**工具回答“能做什么”，技能回答“什么时候用、怎么教”。** 用户不需要知道工具名，也不需要为每个工具学一个按钮。

## 4. 0.6.1 信任层：原规划的升级版

原 0.6.1 是“修 bug 清单”；现在把它升级为 **T1–T7 信任层**。每一项都要回答同一个问题：**如果老师记得你，这些数据能不能被安全地保存、找回、纠错？**

| ID | 原规划 | 升级后的定位 | 最小验收 |
|---|---|---|---|
| T1 | 危险路径补验收 | 可恢复性 | 文稿删除、整库恢复、恢复失败回滚，在隔离库副本上真实点击通过 |
| T2 | 备份加校验 | 可恢复性 | manifest 带 schema、计数、SQLite SHA-256；恢复前 `integrity_check`；坏备份 fail closed，不覆盖当前库 |
| T3 | 搜索承诺对齐 | 可理解性 | 搜索框不再写“知识点”却只搜正文；补“加载更多”和文稿筛选，或明确写“只搜正文和页面文字” |
| T4 | 高亮跨版本 | 记忆连续性 | 文稿换版本后，失效高亮能提示、能清理，不静默变孤儿 |
| T5 | 预算兜底 | 成本可信 | 供应商不返回 usage 时记估算值并标 `estimated`；月份按本地时区；不把漏算伪装成没花钱 |
| T6 | 小窗口/高 DPI | 可用性 | 1366×768、150% 缩放、长提示条、20 条搜索结果不遮挡、不截断 |
| T7 | 按钮级验收 | 可验证性 | CDP 在隔离副本上跑：搜索、加卡、删除、暂停/恢复、高亮、恢复入口；不能只靠接口测试 |

### 0.6.1 的发布口径

- **不新增老师功能**，不扩大 0.6.1 范围；
- 不强制改 schema；能用现有表加校验就先用现有表；
- 真实安装包上重跑 `typecheck`、`test`、`build`、`dist:win`、静默覆盖安装；
- 所有 T1–T7 有新鲜证据后，才允许进入 0.7.0。

### 为什么先做这一层

老师记忆是“长期资产”。如果备份恢复不可信、高亮会丢、搜索承诺不对，所谓“独家老师”就是一次性的角色扮演。**0.6.1 是让 0.7.0 有资格谈长期。**

## 5. 老师人格：稳定、短、可执行

### 5.1 人格基座

默认称呼：**老师**。用户可以在老师档案里改名；用户用“她”称呼时可以保持“她”的口吻，但不伪造真人身份。

建议的基座提示词只保留这些：

```text
你是「{老师名字，默认“老师”}」，学生的本地私教。

你的成功标准不是把答案讲完，而是学生能自己讲出来。
先判断他卡在哪，再决定讲多深；能提问就不要直接灌答案。
学生要直接答案时，先给答案，再补一句为什么。
不编造；不懂就说不懂；不替学生思考，只替他搭台阶。
用短句、具体例子、一次一个动作；不堆术语，不写教科书目录。
不假装是人类，不制造情感依赖，不承诺“只有我懂你”。
```

人格不写成“温柔小姐姐”，也不写成“严师”。**人格靠行为体现**：会不会等学生答、会不会追因、会不会承认不知道。

### 5.2 说话规则

- 先接住学生此刻的问题，再把它接回当前小讲和整门课；
- 每次最多一个追问，不连环问；
- 讲解按现有 `habits` 控制字数：讲透 160–240 字，适中 120–180 字，抓考点 90–140 字；
- 例子优先用学生专业/生活里能懂的具体对象；
- 引用原文时指出页码或块，不把模型自己的话伪装成原文；
- 学生说“直接告诉我”时，切到直接模式，不再苏格拉底。

### 5.3 人格边界

- 不存储与学习无关的隐私、情绪、健康、家庭信息；
- 不主动制造“我离不开你”“只有我懂你”的关系；
- 不因为一次回答就给学生贴“基础差”“不认真”的标签；
- 记忆可以是错的；用户纠正时，旧记忆必须能被覆盖或归档。

## 6. 学生档案：把“独家”落在可检查的数据上

### 6.1 与现有 `habits` 的关系

不推翻 `habits`。它是“讲课偏好层”，继续保留：

- 称呼、 pace、style、minutes、window、avoid；
- 每门课创建时继续冻结 `habits_json`，避免中途改习惯影响已开始的课。

新增的是“学习背景层”：

- 目标：考试 / 入门 / 工作 / 兴趣；
- 当前水平：零基础 / 学过但忘 / 复习；
- 学科与考试日期；
- 每周可投入时间；
- 不适合我的讲法（补充 `avoid` 之外的自由文本）。

### 6.2 三档记忆

老师档案里每条记忆必须带证据等级：

| 等级 | 来源 | 用法 |
|---|---|---|
| 已确认 | 用户明确说“以后都这样”“我就是这个目标” | 可以直接当事实使用 |
| 观察 | 至少两次独立对话/作答出现同一模式 | 可以说“我观察到”，不下绝对结论 |
| 推测 | 单次模糊信号 | 默认不注入提示词；只在老师手记里留待确认 |

### 6.3 记忆条目长什么样

一条记忆不是“学生基础差”，而是：

```text
kind: misconception
subject: 线性代数
concept: 特征值 / 特征向量
statement: 容易把“特征值”和“特征向量”的对应关系说反
evidence: 第 3 讲「停一下」作答把 v 写成了 λ；第 2 次追问仍混
confidence: 0.82
source_session_id: ...
source_document_version_id: ...
user_confirmed: false
```

这类记忆才能指导下一次教学：先问“λ 和 v 谁对应谁”，而不是泛泛地“再讲一遍线代”。

### 6.4 记忆的写入与检索

- **写入**：用户明确陈述 → `已确认`；课后总结提取 → `观察`，每节最多 2 条新记忆；单次模糊信号 → 不写。
- **去重**：同一 `kind + subject + concept` 更新旧条目，不堆重复。
- **容量**：活跃记忆最多 40 条；低置信度、长期未命中的归档。
- **检索**：按当前学科、当前文稿、当前概念关键词匹配；`已确认 > 观察`，新近优先；一次最多注入 6 条、800 字。
- **不做**：第一版不做向量库、不把整段聊天当记忆、不让模型每轮改写人格。

## 7. 老师工具与教学技能

### 7.1 老师工具：对用户隐藏，对老师可用

| 工具 | 用户会怎么说 | 做什么 | 落点 | 约束 |
|---|---|---|---|---|
| `search` 查找 | “上次讲存储矩阵在哪” | 查本地 `search_index`，返回文稿/页/块和原句 | 回答里带原文引用 | 只搜本地库；没命中直说，不编造 |
| `summarize` 总结 | “总结这一讲 / 整份材料” | 按范围生成分层总结 | 课程总结或消息；可存 `lecture_summaries` | 必须引用原文；长度按 habits |
| `outline` 大纲 | “列个复习大纲 / 课程大纲” | 按页/块范围抽结构 | `lecture_summaries.outline_json` 或本课大纲 | 只从材料结构抽，不凭空加章节 |
| `quiz` 题测 | “考考我 / 出三道题” | 生成 1–3 道主动回忆题 | `lecture_quizzes`、`lecture_cards`、错题 | 先答后判；不提前泄露答案 |
| `memory` 记忆 | “记住 / 你记得我什么” | 检索或写入学生记忆 | `teacher_memory` | 推断先“我观察到……”；写入需确认 |
| `notes` 手记 | “下课前记一下” | 写四段式课堂手记 | `teacher_notes` | 只写有证据的掌握/卡点 |
| `read` 读原文 | 内部 | 按版本/页/块取原文 | 提示词上下文 | 不带整库；按需取块 |
| `cards` 卡片 | “加进复习 / 暂停这张” | 新建、暂停、移动卡 | `lecture_cards` / `manual_cards` | 不批量删；破坏性操作要确认 |

**工具调用方式：** 第一版不假设用户模型支持 function calling（很多 OpenAI 兼容端点不支持或格式不一致）。主进程做受控意图路由：先识别“查找/总结/大纲/题测/记忆/手记/卡片”，执行本地工具，再把结果作为上下文交给老师生成回答。一轮最多 2 个工具，工具白名单，不允许任意 shell、网络或文件删除；工具失败就如实说“没查到/没生成”，不拿旧内容冒充。

**工具不是按钮：** 用户说“总结第 3 讲”就能触发；老师页只保留 3 个上下文动作，不把 8 个工具排成 8 个按钮。

### 7.2 教学技能：老师“怎么教”

技能不是工具名，而是**可触发的教学动作 + 输出约束**。第一版只做 7 个，避免技能堆叠。

| 技能 | 触发 | 行为 | 约束 |
|---|---|---|---|
| `diagnose` 诊断 | “带我学”“先问我” | 2–3 个问题定位前置知识，一次一个 | 用户说“直接讲”立即停止提问 |
| `explain` 讲解 | 默认 | 例子 → 规则 → 反例 → 一句话总结 | 引用原文；长度按 habits |
| `socratic` 追问 | “多问我” | 一次只问一个 why/how/如果…会怎样 | 不替学生答；等回答再继续 |
| `quiz` 测验 | “考考我” | 1–3 道主动回忆题；先答后判 | 不提前泄露答案；错题进错题本 |
| `error` 错因 | “我哪里错了” | 概念错 / 步骤错 / 审题错分开 | 不把“粗心”当默认解释；有证据才写 miss |
| `review` 复习 | “安排复习” | 结合到期卡、错题、老师手记排下一坐 | 一次最多 10 张卡，不塞满 |
| `teachback` 复述 | “我讲给你听” | 让学生复述，按原文找缺口 | 不虚假夸奖；只指出具体缺口 |

### 7.3 技能路由

- 默认 `explain`，保持现有“先回答”的体验；
- 用户点按钮时，该技能优先；
- `auto` 模式最多选 1 个主技能 + 1 个辅助技能，不把所有提示词叠在一起；
- 技能失败或模型不遵守时，退回普通讲解，不假装“已完成诊断”。

## 8. 老师手记：把一次课变成下一次课的依据

每门课结束时，新增一份 `teacher_notes`，不是聊天记录，而是四段结构化内容：

```text
summary: 这次真正学到哪里，2–3 句
worked: 哪些讲法有效（例子/对比/追问/复述）
stuck: 哪些概念、步骤、审题还卡
next: 下一次先做什么，具体到“先问什么/先看哪一页”
```

规则：

- 只依据 `study_checks`、对话和原文，不凭感觉写“已掌握”；
- 每节最多 2 条新记忆，避免把一次课过度解读；
- 生成失败不阻断学习总结，手记留空并明确提示；
- 用户能看到“老师这节课记了什么”，可编辑/删除；
- 删除文稿时，关联的 `teacher_notes` 随 `study_sessions` 级联清理；`teacher_memory` 的来源字段置空，但保留为全局学习记忆，除非用户主动删除。

## 9. 提示词编排

### 9.1 分层

```text
系统层：
  1. 人格基座（稳定，≤500 字）
  2. 学生习惯 brief（现有 habitBrief）
  3. 学生档案 brief（目标/水平/偏好，≤300 字）
  4. 相关记忆 brief（最多 6 条，≤800 字）
  5. 当前课上下文（课程总览 / 大纲 / 当前小讲 / 最近 12 条消息）
  6. 当前技能指令（只选 1 个主技能）
  7. 输出约束（引用原文、长度、直接/引导模式）
```

### 9.2 兼容现有调用

- `buildStudyPlanPrompt` 继续接收 `habits`；新增可选 `teacherContext`，没有时行为与 0.6.0 一致；
- `buildStudyChatPrompt` 继续接收 `habits`；新增可选 `profile`、`memories`、`skill`、`mode`；
- `buildStudySummaryPrompt` 不变；新增独立的 `buildTeacherNotePrompt`，失败不阻断总结；
- 所有新增字段都做 `sanitize`，渲染层不能直接拼 prompt。

### 9.3 长度与成本

- 人格 ≤500 字，档案 ≤300 字，记忆 ≤800 字，技能 ≤200 字；
- 总提示词增量控制在 1,800 字以内，避免把上下文挤掉；
- 记忆只注入“相关”条目，不把全部档案塞进去；
- 预算护栏在 0.6.1 修好后，老师记忆的额外调用也计入同一预算。

## 10. 数据模型（建议 schema 11）

0.6.1 尽量不改 schema；0.7.0 迁移到 v11。

```sql
teacher_persona (
  id INTEGER PRIMARY KEY CHECK (id = 1),
  name TEXT NOT NULL DEFAULT '老师',
  pronoun TEXT NOT NULL DEFAULT 'she',
  tone TEXT NOT NULL DEFAULT 'warm-rigorous',
  boundaries_json TEXT NOT NULL DEFAULT '[]',
  version INTEGER NOT NULL DEFAULT 1,
  updated_at TEXT NOT NULL
);

learner_profile (
  id INTEGER PRIMARY KEY CHECK (id = 1),
  goal TEXT NOT NULL DEFAULT '',
  level TEXT NOT NULL DEFAULT '',
  subjects_json TEXT NOT NULL DEFAULT '[]',
  exam_date TEXT NULL,
  weekly_minutes INTEGER NOT NULL DEFAULT 0,

);

teacher_memory (
  id TEXT PRIMARY KEY,
  kind TEXT NOT NULL CHECK (kind IN ('goal','mastery','misconception','preference','strategy','constraint')),
  subject TEXT NOT NULL DEFAULT '',
  concept TEXT NOT NULL DEFAULT '',
  statement TEXT NOT NULL,
  evidence TEXT NOT NULL,
  confidence REAL NOT NULL DEFAULT 0.5,
  source_session_id TEXT NULL REFERENCES study_sessions(id) ON DELETE SET NULL,
  source_document_version_id TEXT NULL REFERENCES document_versions(id) ON DELETE SET NULL,

teacher_notes (
  session_id TEXT PRIMARY KEY REFERENCES study_sessions(id) ON DELETE CASCADE,
  summary TEXT NOT NULL,
  worked_json TEXT NOT NULL DEFAULT '[]',
  stuck_json TEXT NOT NULL DEFAULT '[]',
  next_json TEXT NOT NULL DEFAULT '[]',

ALTER TABLE study_sessions ADD COLUMN teacher_snapshot_json TEXT NOT NULL DEFAULT '';
```

说明：

- `teacher_persona` 只有一行，避免“多个老师”让产品失焦；
- `learner_profile` 只有一行，和 `habits` 分工：一个管背景，一个管讲法；
- `teacher_snapshot_json` 在开课时冻结人格 + 档案摘要，保证同一门课中途改设置不串味；
- `teacher_memory` 的 `source_*` 用 `SET NULL`：删文稿不抹掉“你在矩阵上容易混”这种跨课程记忆，但用户仍可在老师档案里删除；
- `teacher_notes` 随课程删除；它属于那门课，不是全局人格。

## 11. IPC 与界面

### 11.1 新增通道

```text
teacher.profileGet
teacher.profileSave
teacher.memoryList
teacher.memoryUpdate
teacher.memoryDelete
teacher.reset
teacher.noteGet
teacher.noteList
```

`study.send` 增加可选字段：

```text
mode: 'direct' | 'guided'
skill: 'auto' | 'diagnose' | 'explain' | 'socratic' | 'quiz' | 'error' | 'review' | 'teachback'
```

默认 `mode='direct'`, `skill='auto'`，保持 0.6.0 的直接回答体验。

**工具不新增 8 个 IPC 通道。** `search`/`summarize`/`outline`/`quiz`/`memory`/`notes`/`read`/`cards` 的调度都在主进程的 teaching 服务里完成；渲染进程仍然只调 `study.send`，拿到的是“老师回答 + 引用 + 生成物摘要”。这样界面不需要知道工具名，也不给渲染进程开放任意文件/数据库能力。

### 11.2 界面落点：只保留四类固定入口

顶部仍然只有三个 tab：**文稿 / 老师 / 复习**，右边一个设置齿轮。把现在的「AI 私教」改名为「老师」，不新增“总结”“题测”“大纲”“记忆”tab，也不新增第二排工具条。

```text
[文稿] [老师] [复习]                              ⚙
──────────────────────────────────────────────────
老师 · 她记得你什么 ›        课程：06-存储器…
──────────────────────────────────────────────────
左：课程大纲（可收起）    中：当前讲稿 / 老师回答
                          原文引用、公式、例题
                          对话记录（可展开/收起）
──────────────────────────────────────────────────
[继续上次] [考考我] [讲讲这份材料]        [更多]
[ 输入框：直接说“总结第 3 讲”或“我哪里错了”… ] [发送]
直接答 / 带我学
```

- **文稿**：保留现有文稿库、阅读页、划词高亮、全文搜索入口；阅读页的“识别这一页/联网查证”仍留在阅读页，不搬进老师页。
- **老师**：一主一辅。主区是当前讲稿 + 对话 + 输入框；左侧课程大纲可收起；右侧不再常驻“总览与总结”栏，课程总览、学习总结、题测、老师手记统一收进一个“课程资料”抽屉。
- **复习**：保留现有到期卡、错题、手动加卡、暂停/编辑；老师可以把新卡或错题直接送进来。
- **设置**：只放模型、预算、备份恢复、危险操作；老师档案、记忆、习惯不塞进设置页。

### 11.3 能力归属表：哪些不再单独做按钮

| 能力 | 旧界面 | 0.7.0 的做法 |
|---|---|---|
| 总结 | 右侧常驻“生成学习分析总结”按钮 | 用户说“总结这一讲/整门课”；老师在对话里生成，结果进“课程资料”，不占常驻栏 |
| 大纲 | 左侧课程大纲常驻 | 保留左侧可收起大纲（它是课程结构，不是一次性动作）；“列复习大纲”由老师生成后进课程资料 |
| 题测 | 测验/卡片入口分散 | 用户说“考考我”；老师一次出 1–3 题，答完判分，错题进错题本 |
| 查找 | 顶部搜索框 | 保留顶部搜索框作为导航入口；老师调用同一个 `search` 工具做原文引用 |
| 记忆 | 设置/档案里翻 | 老师页头一个“她记得你什么”抽屉；默认只读，用户可确认、修改、删除 |
| 手记 | 无 | 下课时自动生成；在“课程资料”里看，不单独做页面 |
| 复述 | 无 | 收进“更多”里的“我讲给你听”，不常驻 |

**判断标准：** 如果一项能力只是“点一下生成一次”，就不配常驻按钮或独立 tab；如果它需要持续查看状态（课程大纲、复习队列、文稿库），才保留固定位置。

### 11.4 老师页的交互规则

1. 首屏老师动作最多 3 个，且随上下文变化：有课程时是“继续上次 / 考考我 / 讲讲这份材料”；没有课程时是“选一份文稿 / 先问我 / 直接讲”。
2. 所有 8 个工具都必须有自然语言入口；按钮只是提示，不是唯一入口。用户说“总结第 3 讲”“列出这一章的大纲”“我哪里错了”都能直接触发。
3. 生成物必须有落点：总结/大纲/题测进“课程资料”，卡片进“复习”，记忆进“她记得你什么”，手记跟课程走；不能生成完只留在聊天里。
4. 老师回答里引用原文时，显示可点击的“第 X 页”或文稿名；找不到就直说“这份材料里没找到”，不拿相近内容冒充。
5. “更多”只放低频动作，不复制首屏三个动作；菜单层级不超过一层。
6. 破坏性动作仍然二次确认：删除课程、重置老师记忆、整库恢复；这些不能因为“界面简洁”而被藏掉或省掉确认。

### 11.5 界面收敛补充：侧边栏只放“状态”，不放大堆工具

> 2026-11-17 追加。用户提出“很多功能留给老师调用，界面尽量简洁，或者都做成侧边栏按钮”。结论：**采纳“能力归老师”，不采纳“所有工具都变成侧边栏按钮”。**

**为什么不能把 8 个工具平铺成侧边栏：** 用户仍然要记住“总结是哪个、题测是哪个、找原文是哪个”，这等于把旧菜单换个位置；老师也会被降级成“工具栏”。0.7.0 的目标是“说一句话，她自己选工具”，不是“给工具配 8 个图标”。

**固定侧边栏/常驻位置只允许三类：**

| 类型 | 放什么 | 例子 | 判断标准 |
|---|---|---|---|
| 持续状态 | 需要一直看见、会变化的结构 | 文稿库、当前课程大纲、复习队列 | 不是“点一下生成一次”，而是“随时要知道现在在哪” |
| 当前上下文动作 | 最多 3 个，随场景变化 | 继续上次、考考我、讲讲这份材料 | 只在老师页首屏出现，不做全局第二排工具条 |
| 老师状态入口 | 记忆与人格的只读入口 | “她记得你什么 ›” | 默认只读；确认/修改/删除在抽屉里完成 |

**一次性动作一律走自然语言 + 一层“更多”：**

- 总结、题测、列复习大纲、找原文、我讲给你听：不常驻、不单独做 tab；用户直接说，或从“更多”里点一次提示。
- 生成物必须有落点：总结/大纲/题测 → 课程资料；卡片/错题 → 复习；记忆 → “她记得你什么”；手记 → 课程资料。
- 顶部仍然只有 **文稿 / 老师 / 复习** 三个 tab，不新增“总结”“题测”“大纲”“记忆”入口。

**阅读页的边界：**

- 阅读页保留顶部搜索框、划词高亮、当前页“问老师/讲解这一页”的上下文入口；不把老师页的 8 个工具搬进阅读页。
- 首版不做“全屏常驻右侧老师栏”。原因是 1366 宽屏下文稿库 + 正文 + 老师三栏会把正文挤窄；先用“老师页 + 阅读页一键唤起”验证真实使用频率。如果实测发现用户频繁在阅读与老师之间来回切，再考虑把老师做成可收起的右侧面板，而不是现在就加一列。

**一句话验收：** 用户不需要记“总结/题测/大纲/查找/记忆”分别在哪个按钮；在老师页说一句就能触发，结果在课程资料、复习队列或老师抽屉里找得到；屏幕上不出现第二排工具条。

8. 界面不新增顶部 tab，仍是“文稿 / 老师 / 复习”；老师页首屏常驻动作 ≤3 个；“更多”只有一层；

10. 老师手记只依据作答/对话/原文，不出现“已掌握”但无证据；
11. 提示词增量 ≤1,800 字；密钥不出主进程；预算计入老师额外调用；
12. 至少 5 个脚本化学生画像：零基础/复习/赶考试/爱例子/爱定义，讲解策略明显不同；
13. 真实安装包上完成“开课 → 对话 → 工具（总结/题测/查找）→ 手记 → 关闭 → 重开 → 记忆生效”闭环。

## 14. 明确不做

- 云同步、账号体系、手机伴读、端到端同步（用户已否）；
- 多个老师人格/角色市场；
- 语音数字人、3D 形象、情感陪伴；
- 用整段聊天记录当记忆；
- 让模型自主改写人格提示词；
- 用模型“感觉”判定已掌握，替代真实作答；
- 第一版上向量数据库/云 embedding；
- 为总结、大纲、题测、查找、记忆分别做独立 tab 或常驻按钮；
- 让渲染进程直接调用任意工具/文件/数据库；工具只在主进程白名单内执行。

## 15. 风险与取舍

| 风险 | 取舍 |
|---|---|
| 记忆推断错，老师越教越偏 | 三档置信度；观察项不说成事实；用户可改可删 |
| 人格太强，用户赶时间被追问 | 默认直接答；“带我学”显式开启 |
| 提示词变长，成本和延迟上升 | 人格/档案/记忆都设字数上限；只注入相关记忆 |
| 老师变得“像人”，产生情感依赖 | 明示 AI 身份；不做“只有我懂你” |
| 记忆是隐私 | 只存学习相关；本地保存；可导出/重置；备份不含 settings 的密钥 |
| 模型换供应商后人格漂移 | 人格基座独立于模型；用脚本化画像验收 |
| 记忆和文稿版本绑定过死 | 记忆挂概念/学科，不挂单一 block；来源仅作证据 |
| 技能/工具太多，界面变复杂 | 工具全部对用户隐藏；首屏只留 3 个上下文动作；其余走“更多”或自然语言；一次只启用一个主技能 |
| 依赖模型 function calling，换模型就失效 | 主进程做受控意图路由，本地执行工具；不要求供应商支持工具调用 |
| 工具写操作失控或误删 | 白名单 + 一轮最多 2 个工具 + 破坏性操作二次确认；渲染进程不直接执行 |
| 功能藏得太深，用户找不到 | 首屏 3 个上下文动作 + “更多” + 老师第一次使用时提示“你也可以直接让我总结/出题/列大纲” |

## 16. 已拍板与待定

### 16.1 已拍板

1. 老师默认名字是 **“老师”**，不叫“灯下老师”；用户可以在老师档案里改名。
2. 只有一个 **全局人格**；学科差异放在 `teacher_memory.subject` 里，不做多个老师角色。
3. 推断记忆不静默使用；先以“我观察到……”展示，用户确认后才升级为可注入记忆。
4. 先完善 **0.6.1**；代码和测试可以先做，但**不 push、不发 release、不覆盖安装**，等验收后再决定发布。
5. **能力尽量归老师调用，界面做减法**：总结、题测、大纲、查找、记忆不做成一排按钮或独立 tab；顶部保持“文稿 / 老师 / 复习”三个入口，老师页首屏动作 ≤3 个；固定侧边栏只放持续状态（文稿库、课程大纲、复习队列）和“她记得你什么”，不把一次性工具平铺成按钮。

### 16.2 仍待定

1. 老师手记每节课自动生成，还是用户点“记住这节课”？建议下课时自动生成，失败不阻断；用户可选手动刷新。
2. 要不要在第一版做“我讲给你听”技能？它是“能自己讲出来”的直接验收，建议做，但放在最后。
3. 老师档案里的“改名”是否只改称呼，还是也改人格语气？建议只改称呼，语气仍由预设基座控制，避免用户改出不可控人格。

## 17. 设计验收的一句话

**如果 0.7.0 做完，用户应该能说：**

> “她知道我上次卡在哪，这次没有从头讲；她记得我更吃例子，先拿存储矩阵打比方；她也会在我赶时间的时候直接给答案，不强行上课。”

这句话做不到，人格提示词写得再漂亮，也只是角色扮演。

**界面验收的一句话：**

> “我不用记哪个按钮是总结、哪个是出题、哪个是找原文；我只要在‘老师’这一页说一句，她就会做，做完的东西还在课程里找得到。”
