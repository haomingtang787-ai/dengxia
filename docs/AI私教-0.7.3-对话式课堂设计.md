# 灯下 0.7.3 设计稿：一个课件一个对话的三栏课堂

> 状态：0.7.3 已实现（2026-11-17），版本 `0.7.3`；验收记录见 `docs/验收说明-0.7.3.md`。本轮未提交、未发布。  
> 目标：把现在的“文稿工作台”改成“老师工作台”：左栏课程目录、中间一个连续对话、右栏这一讲的知识与工具。  
> 前置：0.7.2 已发布 `v0.7.2`（commit `9cf3dac` / `8f9cb02`，release `447895526`）。

## 0. 一句话结论

**不是把每一讲拆成新对话，而是把一份课件做成一个连续对话，用“讲”做目录锚点和细线分隔。**

一门课（课程）下面有多份课件，一份课件下面有多讲；左栏负责“找得到”，中间负责“聊得下去”，右栏负责“看得清这一讲讲过什么”。

## 1. 现状与可复用资产

| 已有 | 位置 | 这次怎么用 |
|---|---|---|
| 一份课件 = 一个 `StudySession` | `study_sessions` | 直接作为“一个对话” |
| 课件被拆成多讲 | `study_units` | 左栏第三层、右栏当前讲 |
| 每条消息已带 `unit_ordinal` | `study_messages.unit_ordinal` | 中间按讲分组、画细线分隔，**不需要新表** |
| `send` 已接受 `unitOrdinal` | `StudyService.send` | 发消息时把“当前讲”传下去 |
| 生成物已按 `course` / `unit:N` 落库 | `study_artifacts.scope` | 右栏按当前讲过滤 |
| 老师人格、手记、记忆 | `teacher_*` | 右栏“老师手记”，对话连续不丢上下文 |
| 用量与余额核对 | `ai_usage` / `study.usageAudit` | 右栏“这份课件用量”，不按讲拆 |

结论：**0.7.3 主要是界面重排 + 课程分组，不是重写教学逻辑。** 唯一需要动 schema 的是“课程”这一层，以及可选的“按讲记用量”。

## 2. 设计原则

1. **一个课件一个对话。** 讲与讲不隔离，老师始终知道上一讲说过什么。
2. **讲是目录，不是会话。** 点左栏的讲只改变“当前讲”和滚动位置，不创建新对话、不清空历史。
3. **分隔要轻。** 只在讲切换时出现一条细线 + 小字，不做大卡片、不做第二层 tab。
4. **右栏只读。** 知识点、出处、手记、生成物是上下文；总结/题测/找原文仍走对话框的自然语言，右栏最多给“快捷语”塞进输入框。
5. **底部只有一个入口。** 输入框是主入口，模型、技能、用量都收在这一条。
6. **窄屏不硬塞。** 1366 宽右栏自动收成抽屉；左栏可收成图标栏。

## 4. 交互细则

### 4.1 左栏

结构三层：

```text
课程
└─ 课件
   └─ 讲
```

- 课程：可折叠、可改名、可排序；显示课件数。
- 课件：显示文件名 + 讲数；点击后中间滚到对话顶部（开课与总览）。
- 讲：显示 `第N讲 + unit.title`；点击后：
  1. 设置 `activeUnitOrdinal`；
  2. 中间滚到这一讲最近一条消息，或这一讲的“讲首卡”；
  3. 右栏切到这一讲的知识点/手记/生成物；
  4. 输入框 placeholder 变成“问第 2 讲：正交基…”；
  5. **不新增对话、不清空消息、不重新请求模型。**
- 当前讲用 3px 左侧强调条 + 浅底，不用整行变蓝。
- 顶部搜索：输入即过滤课程/课件/讲标题；点结果跳到对应讲。

### 4.2 中间

- 顶部面包屑：`课程 / 课件`；第二行标题：`第 N 讲 · title`。
- 消息按 `unitOrdinal` 分组：
  - `null` 的消息归到“开课与总览”，放在最前；
  - 每当 `unitOrdinal` 变化，插入一条细线分隔；
  - 分隔格式：左右两条 1px 线 + 中间 `第2讲 · 正交基`，11px，颜色 `#8a97a6`；
  - 同一讲内连续追问不重复画线。
- 老师消息：左对齐，头像 + 名字 + 时间 + 内容 + 出处 chip（`p.12` / `第1讲 p.8`）。
- 学生消息：右对齐浅蓝气泡。
- 点击左栏未聊过的讲：
  - 不伪造消息，显示一张“讲首卡”：讲标题、本讲 keyPoints、出处页码、`从这一讲开始问`；
  - 输入框聚焦，发第一条消息后才落库并画分隔。
- 对话很长时：左栏就是目录；后续可加“折叠已学完的讲”，0.7.3 先不做虚拟列表。

### 4.3 右栏

四块，全部只读或“塞快捷语”：

1. **知识点**：当前讲的 `keyPoints`，每条带页码 chip；点 chip 跳原文页。
2. **老师手记**：当前讲相关的“讲通了 / 还卡着 / 下次先做”，来自 `teacherNote`。
3. **这一讲生成物**：按 `scope = unit:N` 过滤 summary/outline/quiz/teachback；显示状态与时间，点击在中间以卡片展开。
4. **这份课件用量**：调用数、输入（命中/未命中）、输出；整份课件合计，不按讲拆。用户已确认按课件总量即可。

右栏底部不放一排工具按钮，只放一条“快捷语”：

```text
想让我做点什么？
[总结这一讲] [考考我] [找原文]
```

点击只是把对应句子塞进输入框，不直接发请求。

### 4.4 底部输入

- 一行 textarea，`Enter` 发送，`Shift+Enter` 换行。
- 第二行：
  - 左：`直接讲解 / 引导我` 切换；`技能：自动`（点开一层小菜单）。
  - 右：`DeepSeek V3 · 已配置`（点开模型设置）；`课件 18.4k`（点开用量核对）；发送按钮。
- 发送时把 `activeUnitOrdinal` 一起传给 `study.send`；消息落库后按讲分组。
- 若当前讲为空，placeholder 显示“问第 2 讲：正交基…”。

### 4.5 新建流程

1. 左栏“＋ 新建课程” → 输入课程名（可留空，默认“未分类”）。
2. 课程内“导入课件” → 选文件 → 现有解析/拆课流程不变。
3. 拆课完成后：
   - 生成一个 `StudySession`（一份课件 = 一个对话）；
   - 左栏自动展开该课程与该课件；
   - 默认 `activeUnitOrdinal = 1`，中间显示第1讲讲首卡 + 老师开场；
   - 不额外调用模型。

### 4.6 对照讲义：不裁剪，拿整页图 + 高亮框

每条有出处的老师回答下面挂一张“对照讲义”卡；总览类回答没有页码就不硬挂。

```text
┌──────────────────────────────────────────────┐
│ 对照讲义 · p.12                       [打开] │
│ ┌────────────────────┐  这一页在讲：        │
│ │  第12页整页缩略图    │  “‖x‖ = √(x,x)”     │
│ │  ┌──────────────┐  │  长度由内积诱导，     │
│ │  │ 高亮框圈住公式 │  │  不是另起一套定义。   │
│ │  └──────────────┘  │  原句：……             │
│ └────────────────────┘                        │
└──────────────────────────────────────────────┘
```

关键做法：

1. **不裁剪。** 直接复用导入时已经渲染好的整页 PNG：PDF 走 `pdf.ts` 的 `renderPage`，PPTX 走 `pptxRender.ts` 的 `renderPptxSlides`。页面图已经存在 `pages.image_relpath`，渲染层用 `app-resource://<previewResourceId>` 显示。
2. **只做高亮。** 用该页 `blocks.locator_json` 里的 `bbox`，在整页图上叠一个半透明黄色框；不裁图、不改原图，页面比例和上下文都保留。
3. **没有 bbox 就退回原句条。** DOCX/TXT/Markdown 没有页面图时，卡片变成“讲义原句卡”：页码 + 逐字原句 + 一句解释，明确标注“这一页没有页面图，按原文对照”，不伪造截图。
4. **PPTX 渲染失败也退回。** 如果 `renderPptxSlides` 没产图，用该页 `slide_text` blocks 按 `bbox` 重建一张 16:9 的纯文字幻灯卡；连 bbox 都没有就退回原句条。
5. **每答最多 2 页。** 超过两页只显示最相关的两页，其余收进“还有 p.16”chip；避免聊天被图片淹没。
6. **默认只展开最新一条。** 历史老师消息把对照卡收成一个小 chip（`p.12`），点一下展开；避免一屏全是缩略图。
7. **点“打开”是页预览弹层。** 不离开对话；弹层显示大图 + 高亮框 + 原句，再给一个“去文稿页”按钮，走现有 `previewFocus`。

老师怎么讲：

- 提示词新增一条硬约束：“先指出看第几页的哪句话/哪个式子/哪张图，再解释；至少引用一处原文；页面上没有的图或公式不许编造。”
- 当前讲的页面文本会作为 `slideBrief` 放进 user 的稳定前缀（在 `unitText` 之后、`最近对话` 之前），同一讲内缓存仍然命中。
- 例：`先看第12页中间这个式子：‖x‖ = √(x,x)。它说明长度不是另起炉灶，而是内积的一种用法。`
- 例：`再看第14页的定义：两个向量正交，就是内积为 0。注意这里说的是“非零向量组”，零向量和任何向量都正交，不能拿它凑正交组。`

为什么这样能落地：

- 不需要新增截图/裁剪管线，导入时已经付过渲染成本；
- bbox 来自解析结果，PPTX 和 PDF 都有；没有 bbox 的格式有明确降级；
- 整页图保留了“这一页还有什么”的上下文，比裁一小块更适合讲题。

## 5. 数据与接口

### 5.1 schema 14

只加课程分组和“对照讲义”引用；**不加 thread 表，也不按讲拆用量**。

```sql
CREATE TABLE study_courses (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

ALTER TABLE study_sessions ADD COLUMN course_id TEXT NULL REFERENCES study_courses(id) ON DELETE CASCADE;
CREATE INDEX idx_study_sessions_course ON study_sessions(course_id, created_at DESC);

ALTER TABLE study_messages ADD COLUMN citations_json TEXT NOT NULL DEFAULT '[]';
```

迁移：

- 现有 `study_sessions` 按 `subject` 分组：同一 subject 建一个课程，`course_id` 指过去；subject 为空归“未分类”。
- 课程名取 subject；同名合并，`sort_order` 按最早会话时间。
- 旧消息的 `unit_ordinal` 保持原样；为 null 的归“开课与总览”。
- 旧消息 `citations_json` 为空；历史回答暂时没有对照卡，只显示页码 chip，不回溯伪造。
- `ai_usage` 不动，右栏按整份课件显示总量。

### 5.2 服务与 IPC

新增：

- `StudyService.courses()`：返回课程 + 每门课的课件 + 每份课件的讲列表（轻量树，不返回消息正文）。
- `StudyService.createCourse({name})` / `renameCourse({courseId,name})` / `reorderCourses({ids})` / `deleteCourse({courseId})`。
- `StudyService.create` 增加可选 `courseId`；未传时按 subject 找/建课程。
- `StudyService.send` 已有 `unitOrdinal`，不新增参数。
- `study.courses` / `study.courseCreate` / `study.courseRename` / `study.courseDelete` IPC；preload 对应暴露。
- 删除课程默认连同其课件会话一起删（`ON DELETE CASCADE`）；二次确认文案写明“会删除该课程下 N 份课件与对话”。如果要保留课件，先把它移到别的课程。
- **对照讲义引用**：`StudyService.send` 在老师回答后生成 `StudySlideCitation[]`，随 assistant 消息写入 `citations_json`；`StudyMessage` 增加 `citations`。
  - 先按当前讲的 `segments.source` / `unit.source` 到该课件的页文本里做逐字匹配，得到候选页码；
  - 再解析回答里的 `[p.12]` / `第12页`，命中则以模型自报页码优先；
  - 每条引用带 `pageNumber`、`pageId`、`quote`、`blockId`、`bbox`（有就带），最多 3 条，展示时只展开 2 条；
  - 页图不存库，渲染层用 `documents.pages` 拿 `previewResourceId`，按 `pageNumber` 映射。
- `buildStudyChatPrompt` 增加 `slideBrief`：当前讲的页码 + 每页原文摘录，位置在 `unitText` 之后、`最近对话` 之前，保持稳定前缀。

不新增：

- `study.thread`、`study.messages(unit)` 之类的新对话接口。
- 每讲独立模型、每讲独立 usage 表。

### 5.3 前端状态

`StudyView` 新增本地状态：

- `activeUnitOrdinal`：当前讲，默认 1；
- `activeCourseId` / `expandedCourses`：左栏展开；
- `rightOpen`：1366 抽屉开关；
- `composerDraft`：右栏快捷语塞入的草稿；
- `pageIndex`：当前课件的 `documents.pages` 结果，用于把 `pageNumber` 映射到 `previewResourceId`；
- `slidePeek`：当前打开的页预览弹层（页码 + 高亮 bbox）。

不把“当前讲”写进数据库，重开课件默认第1讲；如果后续需要“记住上次讲”，再加 `study_sessions.last_unit_ordinal`，0.7.3 不做。

## 10. 风险

| 风险 | 处理 |
|---|---|
| 一份 80 页课件对话很长 | 左栏目录 + 讲锚点；后续再做折叠/虚拟列表 |
| 旧消息 `unit_ordinal` 为 null | 统一归“开课与总览”，不猜讲 |
| subject 为空或写法不一致 | 归“未分类”，允许之后改名合并 |
| 右栏又变成按钮墙 | 只读卡片 + 一条快捷语；动作仍走对话框 |
| 1366 三栏挤 | 右栏抽屉、左栏 240、输入栏两行 |
| 删除课程误伤 | 二次确认写明课件/对话数量；默认级联删除 |
| PPTX 渲染失败 / DOCX 无页图 | 降级为“原句卡”，明确标注没有页面图；不伪造截图 |
| 整页图信息密度高 | 半透明 bbox 高亮 + 原句条；点开可看大图，不强行裁小 |
| 对照卡让聊天变长 | 默认只展开最新一条；历史收成 `p.12` chip；每答最多 2 页 |
| 提示词变长影响缓存 | `slideBrief` 放在 `unitText` 之后、`最近对话` 之前，保持同讲稳定前缀 |
