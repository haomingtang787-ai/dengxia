# 0.7.2 验收说明：用量能对账、缓存更耐用

日期：2026-11-17  
状态：代码实现、全量测试、类型检查、构建与真实 Electron 窗口验收完成；已提交并推送 `master`，tag `v0.7.2`，GitHub release `447895526` 为 latest，安装包已上传并完成本机覆盖安装。

## 一、这次解决的三件事

### 1. token 用量不再把“没回报”当“真实 0”

原来的 `usageOf` 只读 `prompt_tokens_details.cached_tokens`，DeepSeek 顶层回传的 `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` 完全没读；供应商没回 `usage` 时也照常写 `{0,0,0}`，课堂页无法区分“真的没花 token”和“没拿到数字、只能估算”。

现在 `src/ai/client.ts` 导出 `parseAiUsage(body)`，口径：

- `cached = prompt_tokens_details.cached_tokens || prompt_cache_hit_tokens`
- `miss = prompt_cache_miss_tokens || max(0, prompt_tokens - cached)`
- `prompt = prompt_tokens || cached + miss`
- `reasoning = completion_tokens_details.reasoning_tokens`（已包含在 completion 内）
- 响应里没有 `usage` 对象时 `providerReported = false`
- 同时记录响应里的 `model`

`AiUsage` 现在是 `promptTokens / cachedTokens / cacheMissTokens / completionTokens / reasoningTokens / providerReported / model`。`complete()` 与 `describeImage()` 都走同一个解析函数。

### 2. 用量归属不再互相串

删掉了 `StudyService` 上可变的 `usageSessionId / usageVersionId`。改为 `UsageScope` 由调用点显式传入，`client(scope)` 用闭包把归属交给 `recordUsage`：

- `create()` 在第一次模型调用前先生成 `sessionId`，拆课、分段理解、读图的用量直接记到这门课；
- `send()` 用当前 `session.id`；
- `tool()` 用当前 `session.id`；
- `finish()` 的总结也用当前 `session.id`；
- `claimUsage` 只保留给“开课前发生的、没有 session 的读图用量”。

并发两门课同时提问时，后返回的请求不会再把用量记到另一门课名下。

### 3. 前缀缓存优化

DeepSeek 硬盘缓存只匹配“从第 0 个 token 开始完全一致”的前缀，且以 64 tokens 为存储单元。原来的 `buildStudyChatPrompt` 把每轮可能变化的 `skill / mode` 约束放在 system 里，换技能或模式会让整段 system 前缀失效。

现在：

- `system = CHAT_SYSTEM + teacherSystem`（只含老师姓名/语气，整门课固定）
- user 顺序为：老师简报 → 习惯 → 课程总览 → 大纲 → 全课要点索引 → 本讲讲稿 → 最近对话 → 学生现在问 → “请先直接回答” → `modeTail` → `skillTail`
- 同一讲里换技能/模式，system 与 user 的稳定前缀不变，变化只落在最后两段

没有改动 `buildStudyPlanPrompt`，它本来就把重试说明放在末尾。

## 二、存储与接口

schema 从 12 升到 13：

```sql
ALTER TABLE ai_usage ADD COLUMN cache_miss_tokens INTEGER NOT NULL DEFAULT 0;
ALTER TABLE ai_usage ADD COLUMN reasoning_tokens INTEGER NOT NULL DEFAULT 0;
ALTER TABLE ai_usage ADD COLUMN provider_reported INTEGER NOT NULL DEFAULT 1;
ALTER TABLE ai_usage ADD COLUMN model TEXT NOT NULL DEFAULT '';
```

迁移时：

- 旧库全 0 行标记 `provider_reported = 0`，其余标 1；
- 旧行补 `cache_miss_tokens = MAX(0, prompt_tokens - cached_tokens)`；
- 建 `idx_ai_usage_reported`。

`StudyStore`：

- `insertUsage` 写入四个新列；未传 `cacheMissTokens` 时按 `prompt - cached` 补，`providerReported` 未传默认 `true`；
- `usageOfSession` 返回 `cacheMissTokens / reasoningTokens / reportedCalls / estimatedCalls`；
- 新增 `usageKinds(sessionId)`，按 `kind` 聚合、按 `MIN(id)` 排序。

预算与文稿统计的“估算调用数”统一改为 `provider_reported = 0`，不再靠“全 0”猜。

新增 IPC `study.usageAudit`：

- `src/shared/ipc.ts` 加通道并加入 invoke 列表；
- `src/main/ipc.ts` 绑定 `study.usageAudit(body)`；
- `src/preload/index.ts` 暴露 `window.desk.study.usageAudit({ sessionId })`。

`usageAudit` 返回：

```ts
{
  usage: StudyUsage,
  kinds: StudyUsageKind[],
  balance: DeepSeekBalanceInfo[] | null,
  balanceError: string | null,
  officialNote: string
}
```

余额接口只接受 `api.deepseek.com` 官方域名；其他 baseUrl 返回“余额核对仅支持 DeepSeek 官方地址（api.deepseek.com）”。余额查询失败只回错误文案，不影响本机统计。

## 三、DeepSeek 官方 usage 调研结论

- Chat Completions 的 `usage` 里有 `prompt_tokens`、`completion_tokens`、`total_tokens`、`prompt_tokens_details.cached_tokens`、`prompt_cache_hit_tokens`、`prompt_cache_miss_tokens`；`prompt_tokens = prompt_cache_hit_tokens + prompt_cache_miss_tokens`；`completion_tokens_details.reasoning_tokens` 已包含在 completion 中。
- DeepSeek 官方**没有**逐请求 usage 查询 endpoint。公开可用的只有 `GET https://api.deepseek.com/user/balance`，返回 `is_available` 与 `balance_infos[]`（`currency / total_balance / granted_balance / topped_up_balance`）。
- 官方 FAQ 给的“按 API Key 查用量”路径是：登录开放平台「用量信息」页 → 选月份 → 点「导出」→ 解压后看 `amount` CSV（内含分 Key 明细）。
- 因此没有做“自动同步官方 usage”，而是做“本机真实回传 usage + 官方余额核对 + 官方 CSV 导出路径说明”。`officialNote` 直接写清这条路径。

## 四、界面

课堂页“课程资料”抽屉里的 API 用量卡：

- 输入总量，并拆成“命中 / 未命中”；
- 输出总量，若有推理 token 单独标出；
- 前缀缓存命中率与一句解释（命中正常 / 命中偏低的原因）；
- `真实回报 N 次` 与 `估算 M 次`；有估算时显示 warning，说明数字可能偏低；
- “核对官方余额”按钮；
- 点开后显示按 kind 明细（开课拆课、讲解对话、学习总结、读图等）、官方余额、余额错误或 `officialNote`。

说明文案明确：DeepSeek 官方没有逐请求用量接口，按 Key 用量请走「用量信息」页导出 `amount` CSV。

## 六、没有做到 / 仍需注意

1. **没有用真实 DeepSeek 调用做缓存命中率前后对比。** 本轮只改了提示词顺序；真实窗口里的 2% 来自两段拆课调用，不是聊天提示词。同一讲内追问应当命中 system + 课程上下文，切讲、换技能、历史窗口滑动会打断后半段前缀，需要用后续真实对话继续观察。
2. `claimUsage` 对“同一文稿并发开课”的 null-session 读图用量仍有边角风险：本轮修的是模型调用本身的归属，读图用量认领没有加锁。
3. 用量仍按 `prompt_tokens + completion_tokens` 的总 token 数统计，没有按缓存命中/未命中的价格折算人民币；UI 不显示费用估算。
4. 余额查询目前是课程资料里的手动按钮，没有自动刷新，也没有设置页入口。
5. `StudyUsage` 的其他消费方（`LibraryStats`、旧统计 UI）未逐一核对；`LibraryStats` 仍是旧字段。
6. 0.7.1 的真实窗口仍有 `summary / quiz / quiz-grade / teachback` 未逐项点击，只在 fake fetch 测过。
