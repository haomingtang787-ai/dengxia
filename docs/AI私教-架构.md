# 案头 AI 私教：0.3.0 架构与验收口径

## 这次推翻的是什么

0.2.x 的主链路是「逐页自动读懂 → 一次性拆讲」。它能读一页，也能生成一份讲稿，但没有把一份课件当成一门课：

- 没有整份材料的课程设计，课程只对应一个页面；
- 讲稿生成后不再有上下文，学生追问只能重新生成；
- 没有逐句结构，讲解仍然是整段摘要；
- 没有课堂会话和消息持久化；
- 没有结束时的学习分析。

0.3.0 把这些拆掉，换成一条独立链路：

```text
文稿 / 图片 / PPTX / DOCX / PDF / TXT / Markdown
        │
        ▼
整份材料读取（文字块 + 图片页 AI 视觉理解 + OCR 兜底）
        │
        ▼
AI 课程设计（整份总览 + 按习惯拆成小讲 + 每讲逐句讲稿）
        │
        ▼
学习会话（课程、讲稿、消息全部落 SQLite）
        │
        ├── 多轮追问：课程总览 + 当前小讲 + 最近 12 条消息 → 自己的 API
        ├── 小讲切换：每一讲都有原文句、讲解、停一下的问题
        └── 学习总结：根据整门课和对话生成掌握 / 薄弱 / 易错 / 下一步
```

## 数据模型（schema 5）

新增三张表，旧 schema 1–4 不动，旧文库可以原地升级。

### `study_sessions`

一次学习会话。保存整份材料总览、课程大纲、创建时的个人习惯快照、读取警告、是否截断，以及最终总结。

关键字段：

- `document_version_id`：这门课来自哪份文稿；
- `overview`：AI 对整份材料的理解；
- `outline_json`：课程大纲；
- `habits_json`：创建时冻结的个人习惯，后续改习惯不会偷偷改变已经开始的课；
- `warnings_json` / `truncated` / `material_chars`：读取边界必须可见；
- `summary_json` / `status`：`ready` → `finished`。

### `study_units`

一门课的小讲。每一讲保存：

- `source`：原文位置；
- `key_points_json`：必须掌握的点；
- `segments_json`：逐句讲稿，每项是 `source` / `explain` / `check`。

`source` 是课件原文句子或公式，`explain` 是老师口吻的讲解，`check` 是讲完这一句后停一下的问题。每一讲至少两个讲解层次；如果模型只给一个层次，服务会带着错误原因重新请求一次，不把半成品落库。这样“逐字逐句”不是 UI 文案，而是持久结构。

### `study_messages`

课堂消息。`role` 只有 `user` / `assistant`，`unit_ordinal` 记录这条消息发生在哪一讲。每次追问先带课程、本讲和最近消息调用 API，成功后才同时写入学生和老师两条消息，避免模型失败留下半轮对话。

## 服务边界

`src/study/service.ts` 是唯一编排者：

- `create`：检查模型配置 → 读取整份材料 → 课程设计 → 落会话、讲稿、开场；
- `send`：读取会话和当前小讲 → 拼上下文 → 调用 API → 同时落两条消息；
- `finish`：读取整门课和对话 → 生成结构化总结 → 落库并置为 `finished`；
- `list` / `get`：只返回会话视图，不向渲染层暴露密钥。

整份材料读取规则：

1. 文字页按页取 `blocks`；
2. 图片页优先取已有的 AI 视觉理解；
3. 没有 AI 视觉结果时调用视觉模型；失败才退回 OCR；
4. 文本页和图片页都带页码标签进入同一份材料；
5. 最多送 100,000 字，超出时在会话里保存 `truncated` 和提示，不假装读完了；
6. 空页、读图失败会作为 `warnings` 显示，不静默丢掉。

## 个人习惯

沿用已有六项：称呼、讲透/适中/抓考点、先比方/先定义/先提问、一次 15/25/40 分钟、学习时段、避免公式堆/长段落/没例子。

`create` 时冻结成快照写入 `habits_json`，并同时进入课程设计提示和每一轮对话提示。旧的 `habitBrief` 继续复用，避免另造一套习惯语义。

进入「AI 私教」时，如果当前文稿还没有课堂，界面会自动创建，不需要再点一次“拆课”；手动按钮保留为重新开一门或换文稿后的入口。

## 与旧模块的关系

- 旧 `teaching` / `lectures` / `cards` / `quizzes` 保留在库里，但“上课”页不再作为主入口，改为「AI 私教」。
- 旧“本地拆讲”“模型拆讲”按钮已从文稿页移除；文稿页只负责导入、解析、预览、自动读懂，然后进入 AI 私教。
- 复习页暂时保留，继续使用旧卡片数据；新会话的总结不自动生成复习卡，避免把未验证的复习调度混进这一版。

## 失败与恢复

| 场景 | 行为 |
|---|---|
| 没配置模型 | 创建直接被拒绝，提示去「模型」配置，不写半门课 |
| 图片读不出 | 先尝试视觉，失败退 OCR；仍失败则记 `warnings`，课程可以继续 |
| 模型返回非 JSON | 创建/总结失败，返回可读错误，不落半成品 |
| 对话时模型失败 | 不写用户消息，不伪装老师已回答 |
| 重复创建同一请求 | 按 `request_id` 返回已有会话，不重复扣 API |
| 材料超过 10 万字 | 明确保存 `truncated`，界面提示只基于已送部分拆课 |

## 验收

必须从真实入口证明：

1. 真实文库升级到 schema 5，旧文稿仍能打开；
2. 带 API 配置时创建一门课，数据库里同时出现 session、units、opening message；
3. 发送一次追问，消息表有 user/assistant 两条，且请求体包含课程总览、本讲逐句稿和最近消息；
4. 生成总结后 `status='finished'`，总结四组内容可读；
5. 无 API 时创建失败，旧数据不损坏；
6. 全部测试、主进程和渲染层类型检查、构建通过；
7. 安装包覆盖安装后，桌面快捷方式仍指向新版本，真实启动能看到「AI 私教」。

未验证边界：真实第三方视觉模型、超大扫描件、超长多页课件的分块理解、旧复习卡与新总结的联动。
