# 案头 0.2.3 验收说明

## 这一版修正了什么

上一版把 DeepSeek 的模型能力判断错了。根据 DeepSeek 官方 2026-11 的文档：

- `deepseek-chat` 与 `deepseek-reasoner` 已在 2026-07-24 停止使用；旧名字即使还能调用，也会被路由到新模型。
- 现在的 API 模型是 `deepseek-flash`（DeepSeek-V4.1-Flash-1017），原生支持图片输入，支持 JPEG / PNG / GIF / WebP，既可用 base64 data URL，也可用公网 URL 或 Files API。
- 因此「让模型看懂这一页」不需要单独再填一个视觉模型；留空「图像模型」时，直接用 `deepseek-flash` 就能读图。
- 「图像模型」字段保留，只用于换成第三方视觉服务（如 `gpt-4o`、`qwen-vl-max`）时。

所以 0.2.3 做了三件事：

1. 默认模型从 `deepseek-chat` 改为 `deepseek-flash`。
2. 读取旧配置时，如果地址是 `api.deepseek.com` 且模型名是 `deepseek-chat` / `deepseek-reasoner` /
   `deepseek-v4-flash` / `deepseek-v4-flash-vision-exp`，自动迁到 `deepseek-flash`。
   自定义网关地址不改，避免把别的服务商模型名改坏。
3. 模型弹窗和页面按钮的提示改成「`deepseek-flash` 原生支持图片」，不再说 DeepSeek 不能读图。
   读图请求的 `max_tokens` 从 900 提高到 2400，避免思考过程把输出额度吃光。

## 搜索能力（已确认，但本轮未接入界面）

DeepSeek 现在有两类搜索能力：

- 独立接口：`POST https://api.deepseek.com/v1/tools/search` 搜索网页，
  `POST https://api.deepseek.com/v1/tools/fetch` 抓取网页正文。
- 对话内联网工具：`deepseek_web_search`（搜索、深度思考搜索、图片搜索）和
  `deepseek_read_url`（读取消息里的链接），由服务端执行并附引用。
  Responses API 的 `web_search` 目前只在 `deepseek-v4-pro` 下支持。

0.2.3 没有把搜索接进「案头」的界面；本轮只修正图片识别和默认模型。搜索可以下一版单独做
「读完这一页后联网查证」，避免把视觉识别和联网混在一次请求里，出了问题不好分开。

## 五分钟验收

1. 双击桌面「案头」，点「模型」。
2. 确认模型名默认是 `deepseek-flash`；如果之前存过 `deepseek-chat`，打开后应该已经变成
   `deepseek-flash`。
3. 粘贴 DeepSeek 密钥，点「保存」。
4. 导入一张带中文的图片，点「让模型看懂这一页」。
5. 应该出现「模型读图 · deepseek-flash」卡片，而不是提示模型不支持图片。
