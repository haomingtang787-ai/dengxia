# 灯下 0.5.0 验收说明：改名、图标、检查更新与发布

> 验收对象：`DengXia-setup-0.5.0.exe`
> 时间：2026-11-16

## 这一版做了什么

1. **应用改名**：产品名由「案头」改为「灯下」。
   - 影响范围：窗口标题、左上角品牌、浏览器标题、提示词自称（「你是『灯下』的课程设计师…」）、安装包/程序显示名。
   - `appId`（`local.desk.teacher-agent`）保持不变，覆盖安装能识别为同一应用。
   - 用户数据目录由 `%APPDATA%/案头` 变为 `%APPDATA%/灯下`，**首次运行是全新状态**（不带旧对话数据）。

2. **图标**：新增 `scripts/build-icon.mjs`，用 `@napi-rs/canvas` 本地绘制「灯下」标志——深青绿圆角底、一盏摇臂台灯把暖色灯光洒向一本摊开的书。
   - 产出 `build/icon.png`（1024）、`build/icon.ico`（256）、`resources/icon.png`（窗口图标）。
   - 已接入 `electron-builder.yml`（安装包/卸载程序图标）与主窗口图标。
   - 改配色或形状后重跑 `node scripts/build-icon.mjs` 即可。

3. **UI**：左上角品牌区加入内联台灯 logo，标题与说明文字排版对齐；主界面沿用 0.4.2 的三栏独立滚动 + 窄窗对话抽屉布局。

4. **「检查更新」**：模型弹窗底部新增版本号与「检查更新」按钮。
   - 主进程 `src/app/info.ts` 提供 `AppInfoService`，`checkUpdate()` 是**占位实现**：设置环境变量 `DENGXIA_UPDATE_REPO=owner/repo` 后，用本机已登录的 `gh` 拉最新 release tag 对比版本号；未设置则提示「未配置更新源」。
   - 你可以在 `checkUpdate()` 里换成自己的更新源（自有服务器 / 对象存储等），这是明确的接缝。

5. **数据保留约定**（写进代码注释，每次更新都要遵守）：更新只替换应用文件，绝不删除/清空 `userData`（`%APPDATA%/灯下`，含 `library.sqlite` 与 `originals/artifacts`）；产品名「灯下」保持稳定，否则数据目录会漂移。

## 验收结果

- 两套 `tsc --noEmit` 通过；`vitest run` **31 文件、171 项全部通过**；`npm run build` 通过。
- `npm run dist:win` 通过，产物 `DengXia-setup-0.5.0.exe`。
- 窗口冒烟（本地假模型）：
  - 左上角品牌「灯下」+ 台灯 logo 正常显示；
  - 模型弹窗底部「灯下 0.5.0」版本号与「检查更新」按钮正常；
  - 课堂完整链路（自动拆课 → 停一下作答 → 两轮追问 → 学习总结）照常跑通，滚动结构 `bodyScrolls:false`。

## 尚未验证

- 安装包在**干净机器**上的覆盖安装、桌面/开始菜单快捷方式与图标展示未实测。
- 「检查更新」的真实 gh 流程未端到端验证（需设置 `DENGXIA_UPDATE_REPO` 后点一次按钮）。
- 改名后旧版「案头」数据目录不会自动迁移到「灯下」（本版按全新启动处理，符合「不保留旧对话数据」的要求）。

## 发布
