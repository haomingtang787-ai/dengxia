> 2026-11-16 更正：本文档当时误以为 DeepSeek 文本模型不能读图。DeepSeek 官方现已用

## 这一版新增

- **识别图片和扫描件里的文字**：页面工具栏点「识别这一页文字」，调用 Windows 自带的
  `Windows.Media.Ocr`，在本机离线跑，不联网、不装第三方模型、不需要密钥。
  识别结果会合并汉字之间多余的空格，保存到这一页，之后「本地拆讲 / 模型拆讲」会把这段
  文字一起带进原文。
- **让模型看懂这一页**：页面工具栏点「让模型看懂这一页」，把这一页预览图压到长边 1600 的
  JPEG，发给当前配置的 OpenAI 兼容模型，要求它抄出图中文字并说明图表、结构、公式之间的关系。
  结果同样落库，显示为「模型读图」。
- **新增可选「图像模型」**：模型弹窗里多一个「图像模型（可选）」输入框。0.2.2 当时误判
  DeepSeek 文本模型不能读图，所以建议填一个支持图片的模型（如 `gpt-4o`、`qwen-vl-max`）；
  0.2.3 已更正：默认 `deepseek-flash` 可直接读图，这个字段只在换第三方视觉服务时填。
- 图片导入时的旧提示「光学字符识别和视觉理解都未实现」已经改掉，不再误导。

## 五分钟验收

1. 双击桌面「案头」。
2. 导入一张带中文的图片（PNG / JPG）或扫描件 PDF。
3. 文稿页页面工具栏点「识别这一页文字」：
   - 顶部提示「识别到 N 个字」；
   - 页面上出现「识别出的文字 · windows-ocr」卡片；
   - 中文之间不会出现「案 头 O C R」这种被拆开的空格。
4. 点「让模型看懂这一页」：
   - 需要先在「模型」里填一个支持图片的模型和密钥；
   - 成功后出现「模型读图 · 模型名」卡片，内容包含「图中文字」和「讲解要点」。
5. 点「本地拆讲」，确认大纲里带上了识别出的文字。

## 已知边界（不要当成已做）

- Windows OCR 只在 Windows 有效；这台机器只装了 `zh-Hans-CN` 语言包。中文印刷体可用，
  英文和公式会出现字符级误识别：实测 `CO2` 被识成 `C02`、`H2O` 成 `H20`、`->` 成 `一 >`、
  `Glucose` 成 `GIucose`。代码没有做化学式纠错，避免把正确内容改坏；需要精确公式时用
  「让模型看懂这一页」，或人工核对。
- OCR 只对「有预览图的页面」开放；没有渲染页的文稿只能用文字解析。
- 视觉理解依赖用户自己的 OpenAI 兼容视觉模型和密钥。**真实第三方视觉接口没有验证**，
  本轮用的是本地假模型；DeepSeek 文本模型不支持图片，必须另填图像模型。
- 识别结果保存在 `image_readings` 表，按页和类型各保留一条；重复识别会更新同一条。
- 密钥仍明文保存在本机 `settings.json`，只留主进程，不下发给界面。
