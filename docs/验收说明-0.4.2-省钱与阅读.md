# 案头 0.4.2 验收说明：省钱与阅读体验

> 验收对象：`dist/desk-setup-0.4.2.exe`
> 时间：2026-11-16
> 范围：① 降低真实 API 花费（分段理解复用、前缀缓存友好、用量可见）；② 课堂界面滚动与布局重做。

## 一、和豆包那份 0.4.0 对比后的结论

两份工程是同一项目的平行演进。逐文件对比后，可以借鉴的部分**已经在副本里**：

| 豆包版 0.4.0 的做法 | 副本（0.4.1 起） | 结论 |
|---|---|---|
| `AiClient` 对 408/429/5xx 重试 3 次、指数退避 | 同实现（同源） | 无需移植 |
| 视觉长边 2048、JPEG 88，提升公式小字可读性 | 同实现 | 无需移植 |
| 纯 JS 逐页渲染 PPTX（不依赖 LibreOffice） | `pptxRender.ts` 同实现 | 无需移植 |
| 80 页整份材料直接进拆课（上限 20 万字） | 改为按页切段逐段读懂（上限 60 万字） | **保留副本方案**：整份直送在 20 万字以上会撞上下文和输出上限 |
| 讲稿 prompt 只有「材料全文」 | 分段理解 + 逐字摘录 + 接地校验 | 副本更严，不动 |

唯一值得吸收的是它的**验收记录方式**（把安装版实测数据、SHA-256、快捷方式路径写进验收文档），本文件沿用这个格式。

## 二、省钱：三处真实改动

### 1. 分段理解结果持久化（最大头）

之前每次「开课」都会重新跑一遍逐段读懂：82 页 PDF 是 12 次大输入调用。现在：

- 新增表 `material_digests(document_version_id, material_sha, chunk_count, rendered_text, digests_json, warnings_json)`；
- 开课时先算材料 SHA-256，命中即直接复用，课程警告里明确写「已复用上一次对这份课件的逐段理解结果（N 段）」；
- 材料一变（重新解析、换版本）哈希不同，自动失效重算。

效果：同一份课件第二次开课（换习惯、重开一门、误点）**不再为读材料付费**，只剩一次拆课调用。

### 2. 重试提示移到末尾，让前缀缓存整段命中

DeepSeek 的上下文缓存按前缀匹配计费（命中部分约为原价 1/10）。原来拆课/分段理解重试时，把「上一次输出不合格……」放在提示最前面，整个前缀全部失效。现在：

- 重试说明追加在末尾；
- 前缀（系统提示 + 习惯 + 全部材料/分段理解）与第一次**逐字一致**，重试只花末尾增量的钱。

有测试锁死这一行为（`tests/study-cost.test.ts`：「拆课重试把不合格说明放末尾，前缀与第一次完全一致」「分段理解重试同样只增末尾」）。

### 3. 用量可见：知道钱花在哪

- 新增表 `ai_usage(kind, prompt_tokens, cached_tokens, completion_tokens, session_id, document_version_id)`；
- `AiClient` 从响应 `usage.prompt_tokens_details.cached_tokens` 读取缓存命中，按调用类型（digest / plan / plan-repair / chat / summary / vision / vision-embedded / research）落库；
- 开课阶段的读图与分段理解在建好课后自动归到这门课名下（`claimUsage`）；
- 课堂右栏新增「API 用量」卡片：调用次数、输入/输出 token、**前缀缓存命中率**。

## 三、界面：滚动与布局重做

问题：`.app` 用的是 `min-height: 100vh`，整窗一起滚。读一份长讲稿时，左侧大纲、右侧总览全被带走，输入框要滚到最底才看见。

改动：

1. `.app` 改为固定视口高度，滚动只发生在面板内部；
2. 课堂视图三栏各自滚动：左大纲、中讲稿、右总览/总结，互不牵动；
3. 宽屏（>1440px）：讲稿占列高 60%，对话固定 300–460px 且在框内滚动，输入框常驻；
4. 窄窗（≤1440px，默认 1280 窗口即属此档）：
   - 总览/总结变成底部信息带（96–168px，内部滚动），不再按内容撑高把讲稿挤成 0；
   - 对话改成右下角抽屉，按钮显示「课堂对话 · N」，点开是 460×74% 的面板，讲稿独占整列高度；
5. 换讲时讲稿自动回顶，左侧当前讲滚进视野；
6. 新消息自动滚到底；
7. 滚动条统一 9px 细条，减少滚动时的跳动感；
8. 课堂标题区压缩（标题 22px、对话头部说明在课程内隐藏），把高度让给正文。

## 五、没验证的（不能当成通过）

1. **没有再用真实 API 跑一遍**。这一轮为了不再花钱，全部用本地假模型和单测验证；真实模型下的缓存命中率与省钱幅度要等你下次开课时看右栏「API 用量」卡片的实际数字。
2. 分段理解的复用只对**同一份材料再次开课**有效；第一次开课仍要付读材料的钱（这是必要成本）。
3. Windows 安装包 0.4.2 已重打，但未在干净机器上做覆盖安装验证。
4. DeepSeek 的缓存命中依赖服务端 64-token 块匹配，短提示词（如单次追问）命中会偏低，卡片上已写明这一点。

## 六、复验步骤

1. 安装 `dist/desk-setup-0.4.2.exe`；
2. 用一份 ≥6 万字的课件（如 82 页 PDF）开课，记录右栏「API 用量」的调用数与命中率；
3. 同一份课件再点「用当前文稿再开一门」，确认警告里出现「已复用上一次对这份课件的逐段理解结果」，且调用次数明显少于第一次；
4. 拖动窗口宽度跨过 1440px，确认右侧栏在「第三栏」与「底部信息带」之间切换；
5. 窄窗下点右下角「课堂对话」展开抽屉，确认输入框常驻、新消息自动滚到底；
6. 在长讲稿里上下滚动，确认左侧大纲与底部信息带不跟着动。
