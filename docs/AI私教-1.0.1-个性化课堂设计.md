# 灯下 1.0.1 设计稿：把一份课件上成一门因人而异的课

> 状态：设计稿，未实现。  
> 基线：`0.7.5`，当前提交 `ae66f48`（2026-11-17）。  
> 目标版本：`1.0.1`。  
> 这次不是再做一层 UI 皮肤，而是把产品从“会聊课件的聊天框”改成“会持续教一个人的老师”。

## 0. 先对齐用户真正要的东西

用户原话：

> 无论我提供什么文件课件，或者资料，或者提问问题，它都可以像一个个性化老师一样为我解答讲解，起码要让我听得下去，最后进行复习总结知识点。但是这些好像什么样的 AI 和 agent 都可以做到，唯一不同的就是讲解到底有多详细、多个性化、多贴合。

这段话里真正的产品要求不是“能答”，而是五个词：

1. **详细**：不是把整页文字倒出来，而是按学生的接受速度拆成能消化的步子。
2. **个性化**：知道这个学生怕公式、容易走神、上次错在哪、喜欢先看例子还是先看定义。
3. **贴合**：讲的是这份课件的这一页，不是泛泛的教科书知识。
4. **听得下去**：一次只讲一个概念，有例子、有停顿、有检查，不堆砌。
5. **复习总结**：讲完不是结束，而是留下知识点、卡片、题测、错题和下一次复习。

任何 AI 都能回答一次问题。灯下 1.0.1 要证明的是：

> **同样的问题，豆包给你一个正确答案；灯下给你一节你知道从哪页来、为什么这样讲、下一步做什么、明天还记得住的课。**

这是唯一值得继续做的差异。否则直接用豆包更划算。

## 1. 0.7.5 已经有什么

| 已有资产 | 现在能做到 | 1.0.1 怎么用 |
|---|---|---|
| `StudyCourseTree` / `StudyCourseSession` / `StudyUnit` | 课程、课件、讲三级结构，一份课件一个连续对话 | 作为首屏“课程状态”和左栏目录，不再只当导航 |
| `StudyMessage.unitOrdinal` | 消息按讲分组，讲与讲不拆会话 | 继续用它判断“学到哪、上次停在哪” |
| `StudySlideCitation` | 老师回答带页码、原文、pageId、bbox | 升级成每条讲解的“页证据条”，不只显示一个小 chip |
| `StudyUnit.segments` | 原文 / 讲解 / 停一下 三层 | 作为讲解节奏的骨架，不重新发明教学结构 |
| `StudyCheck` | 学生作答落库，进入学习总结 | 作为个性化证据：答对/答错/答不出都影响下一轮讲法 |
| `StudyArtifact` | 总结、大纲、题测、查找、复述 | 变成“今日计划”的输入，不再只是右栏里的一份文件 |
| `TeacherPersona` / `LearnerProfile` / `TeacherMemory` / `TeacherNote` | 老师人格、学员画像、学科记忆、老师手记 | 让“她记得你”出现在回复里，可查看、可修改 |
| `TeachingCard` / `TeachingMiss` / `ReviewView` | 卡片、错题、五箱复习、导出 | 与新的学习页共用一套学习账本 |
| `StudyUsage` / `ai_usage` | 按课件统计调用、缓存命中、余额核对 | 保持本地可见，不因个性化把成本藏起来 |
| 0.7.5 三栏课堂 | 左课程 / 中对话 / 右上下文，淡青纸色 + 深绿主按钮 | 保留壳，改的是壳里的“教学状态” |

结论：**1.0.1 不重写导入、拆课、对话和复习，而是把已有的教学资产组织成“一个老师在上课”。**

## 2. 为什么现在还是像豆包

### 2.1 外壳同质化

左栏课程、中间对话、右栏上下文、底部输入和模型选择——这套壳本身没有错，但它和豆包/Codex/通用 Agent 太像。用户第一眼看到的是“另一个聊天框”，接下来自然会拿豆包最强的维度来比较：

- 模型能力；
- 文件上传和解析；
- PPT 页面的清晰度；
- 多模态和生态；
- 移动端和账号体系。

这些维度我们都不占优，也不应该去争。

### 2.2 真正的差异藏在侧栏里

课程地图、页码证据、老师记忆、错题和复习队列，现在大多在右栏或二级页。首屏仍然是一句“今天想学什么？”和一个空白对话。用户必须先学会这个产品，才能看到它和豆包的不同；这等于没有差异。

### 2.3 右栏五个动作是工具，不是教学策略

复习资料、一键卡片、题测、错题本、个性化辅导——任何聊天机器人都能长出这五个按钮。它们证明“功能在”，但不能证明“这个老师会教”。

### 2.4 预览清晰度不是靠 UI 能追上的

我们的 PPTX 页图依赖本地渲染/转换，字体、版式、图片保真度很难和云端文档管线比；不装 LibreOffice 时 Office 预览还有额外限制。**如果核心体验是“把 PPT 看清楚”，豆包和原版 PowerPoint 都更强。**

1.0.1 的策略不是“预览比豆包清楚”，而是：

- 页图用于**证据和定位**，不是替代原文件；
- 提供高 DPI、缩放、“打开原文件”；
- 对本地合成页明确标注，不假装高清；
- 把“这句话来自第几页、点一下能回去”做成豆包不容易做到的体验。

## 3. 1.0.1 的定位

### 3.1 一句话

> **灯下 = 课件原生、每句话有出处、讲完能复习、记得这个学生的本地私教工作台。**

不是“另一个能读文件的聊天框”，也不是“更聪明的总结工具”。

### 3.2 三个承诺

1. **听得下去**：一次一个概念，先定位、再白话、再例子、再停一下。
2. **讲得对**：每个事实尽量回到课件原页；回不去的明确标成讲解/归纳。
3. **记得住**：每讲结束留下总结、卡片、题测和下一次复习，不靠用户自己整理。

### 3.3 角色、记忆与输入边界

- 老师默认称呼“老师”，学生可在老师档案里改名字、代词和语气；1.0.1 仍然只有一个老师，不做多角色切换。
- 记忆分三层：全局人格与底线、学科记忆、课程/讲手记。学生能看到“她记得你什么”，能改、能停用、能删除；推测必须先确认。
- 导入范围沿用现有实现：PPTX、DOCX、PDF、TXT、Markdown、PNG、JPEG；旧 `.ppt` / `.doc` 明确要求另存为新格式，不假装支持。
- 允许学生直接提问课程外的问题；有课件依据时带页证据，没有依据时标“讲解/归纳”，不强行编造页码。

### 3.4 不做什么

- 不做多老师角色；
- 不做云同步、账号、手机伴读；
- 不做通用 Agent 工具市场；
- 不把右栏做成按钮墙；
- 不承诺“PPT 预览比豆包清晰”；
- 不为了“像豆包”继续加通用聊天功能。

## 4. 教学模型：从“回答”到“一节课”

### 4.1 一条讲解的基本配方

每个讲解步只做一件事，建议 3–6 分钟：

```text
定位：这一页在讲什么（一句话）
原文：只引和当前概念有关的一两句
白话：用学生能听懂的话解释，一段只放一个意思
例子/对比：一个具体例子，优先用学生熟悉的东西
停一下：只问一个检查问题，等学生答
```

不把“定义、性质、推导、例题、总结”一次性全倒出来。学生答完再进入下一步。

### 4.2 学员画像

画像不是一段空泛的人设，而是四类可用证据：

| 来源 | 内容 | 用途 |
|---|---|---|
| 明说 | `LearnerProfile` / `HabitsView`：目标、水平、节奏、风格、每次时长、避免项 | 决定默认讲法和长度 |
| 观察 | `StudyCheck`：答对、答错、答不出；追问长度；反复问同一处 | 决定是否降维、补例子、重讲 |
| 课程 | 当前讲、已学讲、`keyPoints`、`summary.next` | 决定先讲什么、不重复什么 |
| 记忆 | `TeacherMemory`、`TeacherNote`、错题 | 决定“这次要避开/要接着上次的什么” |

`HabitsView` 现在有 `pace / style / minutes / window / avoid`。1.0.1 增加一个 **讲解深度** 维度：

```ts
type StudyDepth = 'detail' | 'standard' | 'fast'
// detail：细讲，多个例子、多次停顿
// standard：标准，一例一停
// fast：速通，先结论/考点，例子按需
```

深度是**可改的默认值**，不是硬编码：用户可以在输入栏切，也可以在老师回复后点“再通俗一点 / 举个例子 / 直接考我”。

### 4.3 讲法选择

老师不要每段都用同一种讲法。按学生画像和当前内容选一个主讲法：

| 讲法 | 适合 | 行为 |
|---|---|---|
| `analogy` 类比 | 怕公式、第一次接触 | 先用生活例子，再回到定义 |
| `definition` 定义 | 喜欢严谨、要考试 | 先给定义和条件，再举例 |
| `example` 例题 | 会背不会用 | 从一道题反推概念 |
| `contrast` 对比 | 总混淆两个概念 | 用对照表/反例区分 |
| `socratic` 提问 | 喜欢被追问、想自己想 | 一次一个问题，不直接给答案 |
| `drill` 训练 | 临近考试、要熟练 | 先考点，再限时练 |

默认映射：

- `style = story` → `analogy`
- `style = define` → `definition`
- `style = ask` → `socratic`
- `pace = exam` → `drill`
- 学生说“听不懂/太抽象” → 降一档，换 `analogy`
- 学生说“太慢/直接考试” → 升一档，换 `drill`
- 检查答错 → 先诊断误解，再用 `contrast` 重讲，再给一道相似题

### 4.4 讲解深度

| 深度 | 输出 | 停顿 | 例子 | 适合 |
|---|---|---|---|---|
| 细讲 | 约标准 1.5–2 倍 | 每个概念后都停 | 2–3 个，含反例 | 基础薄弱、第一次学 |
| 标准 | 正常长度 | 每个关键点停一次 | 1 个 | 大多数情况 |
| 速通 | 约标准一半 | 只在一讲结束停 | 0–1 个，偏考点 | 复习、考前 |

深度只影响“讲多细”，不影响“讲得对”：无论哪一档，事实都必须有页证据或明确标成归纳。

### 4.5 讲完之后的固定动作

一讲结束（手动点“讲完了”或系统判断最后一段已答完）后，必须产出四件事：

1. **本讲总结**：一句话主旨 + 3–5 个知识点。
2. **掌握判断**：已掌握 / 还不稳 / 易错，引用学生作答证据。
3. **记忆材料**：3–5 张卡，优先从 `keyPoints` 和错题生成，不重复已有卡。
4. **下一动作**：2–3 道题测，或 1 个“明天先复习这个”的条目。

这四件事直接进入右栏“今天”和复习页，不要求用户自己去点五个按钮。

### 4.6 “讲得好”的判断标准

1. **听得下去**：一段不超过 4 行；一屏只出现一个核心概念；每 3–6 分钟有一个检查。
2. **贴合**：解释里至少有一处当前课件原句/页码；不出现脱离课件的长篇教科书。
3. **个性化**：一讲里至少使用一次画像/记忆/错题证据，并且用户能在界面上看到“这次用了什么”。
4. **能复习**：讲完有总结、卡片、题测、下一次复习，不是“讲完就散”。

## 5. 六个硬升级

这六项就是 1.0.1 的范围。按“用户先感知什么”排序，不按代码模块排序。

### 5.1 首屏露出课程状态

**现状**：首页是老师气泡 + 导入/新建；有课程时打开也只是对话，用户不知道“上次停在哪、今天该干什么”。

**改成**：对话上方加一条 44px 左右的“今日课堂条”，不是仪表盘。

```text
第 3 讲 · 正交基       上次停在 p.12    今天复习 3 张
[继续这一讲]           [先复习 3 张]      [导入新课件]
```

- 有三门课但未选课：中间显示“最近课程”两张卡，带进度和“继续”，不是空白。
- 无课程：保留现在的老师气泡 + 导入/新建，不额外加营销步骤。
- 课程页右上角仍可看“整份课件 / 更多”，不抢主行动。

**验收**：打开应用 3 秒内能说出“我在学什么、上次到哪、下一步点什么”。

### 5.2 每条老师回复带页证据

**现状**：引用以页码 chip 存在，页图预览在别处；用户要自己把讲解和原页对上。

**改成**：有 `StudySlideCitation` 的老师消息，下面出现一条 **页证据条**：

```text
┌──────────────┐  第 2 页 · 原文
│  整页缩略图   │  “1(α,β)=α1β1+α2β2+…”
│   bbox 高亮   │  [打开原页]  [复制引用]
└──────────────┘
```

- 默认最多显示 2 条，更多收进“还有 2 页”。
- 点缩略图或页码打开整页预览，保留 bbox，不裁剪页图。
- 没有引用的回答，明确标“讲解/归纳”，不伪造页码。
- 题测解析、错题复习、总结里的关键结论同样带页证据。
- 1366 宽时证据条放在消息下方，横向不溢出。

**验收**：任取一条带引用的回答，点页码能打开正确页，原句能在页图中高亮；引用对不上时显示“定位到页”而不是假 bbox。

### 5.3 右栏从“按钮墙”变成“今日计划”

**现状**：右栏顶部是“学习动作”五按钮，功能都在，但看起来像通用 Agent 工具面板。

**改成**：右栏第一块是“今天”，最多三行，每行一个明确动作：

```text
今天
○ 复习 3 张到点卡片        [开始]
○ 重做 2 道错题            [开始]
● 继续第 3 讲 · 正交基      [继续]
```

- 每行只做一个动作；没有数据时显示“先学完这一讲，复习会自动排”。
- 原来的五个动作保留，但收进下方可展开的“更多学习动作”，不再占据第一屏。
- 顺序固定：复习 → 错题 → 继续当前讲。用户一眼知道先做什么。
- 右栏仍保留：知识点、这一讲的题、老师手记、这一讲生成物、这份课件用量、本地优先 footer。

**验收**：右栏首屏不出现五个并列按钮；用户能在 3 秒内选出今天第一个动作。

### 5.4 错题闭环真正闭合

**现状**：学习页题测的批改结果存在 artifact 里，没有写入 `TeachingService` 的错题本；右栏“错题本”和复习页用的还是旧 teaching 数据。这是目前“学习闭环”最大的假点。

**改成**：建立一套课程绑定的学习账本。

```ts
type StudyMiss = {
  id: string
  courseId: string
  sessionId: string
  unitOrdinal: number
  documentVersionId: string
  pageId: string | null
  quote: string | null
  prompt: string
  explain: string
  sourceKind: 'quiz' | 'check' | 'teachback' | 'manual'
  box: number
  due: number
  lastGradedAt: string | null
}
```

- 答错（选择题、开放题、复述缺口）→ 写入错题，`box=1`，立即到期。
- 再次答错 → 不重复建条目，只更新 box/到期时间。
- 答对 → 进入下一箱，复习页和右栏同步。
- 右栏错题数、复习页错题本、错题重练都查同一份账本。
- 旧 `lectureId` 数据保留只读，不强行迁移；新数据必须带课程/讲/页。

**验收**：
1. 在学习页答错一道题，右栏错题数立即 +1；
2. 打开复习页能看到同一道题和页码；
3. 在复习页答对，箱子前进，右栏数字不重复增长；
4. 从错题点回原页，能定位到对应页。

### 5.5 预览不硬争清晰度

**现状**：Office 页图依赖本地转换/合成；LibreOffice 不是打包依赖；和豆包的云端文档管线比清晰度必输。

**改成**：

1. **PDF 优先**：pdfjs 用更高 scale 渲染，缓存整页图，默认适配宽度，可 200% 放大。
2. **PPTX/DOCX**：检测到受控 LibreOffice 时，先转 PDF 再高 DPI 渲染；没有时用内嵌图/本地合成页，并明确标注“本地合成，以原文件为准”。
3. **打开原文件**：预览工具条提供“打开原文件”，交给系统默认应用；不在应用内假装替代 PowerPoint/WPS。
4. **证据优先**：页图用于页码、bbox、引用，不宣称“比豆包清晰”。
5. **失败可见**：空白页、字体缺失、转换失败都提示，不静默显示白图。

**验收**：
- 1600 宽下正文页在 100% 下可读，200% 放大不糊成块；
- 点“打开原文件”能打开真实文件；
- 无 LibreOffice 时页面有明确降级提示；
- 不出现“我们比豆包清晰”的文案。

### 5.6 让“她记得你”可见

**现状**：老师人格、学员画像、`TeacherMemory`、`TeacherNote` 都在，但学生感知不到“这次回答用了我什么”。

**改成**：

- 右栏顶部或老师档案里有一张“她记得你”卡，只显示 3 条当前有效的记忆：
  - “你怕一上来全是公式”
  - “你每次只想学 25 分钟”
  - “上次正交和线性无关混淆过”
- 每条可编辑、停用、删除；推测类记忆必须先确认。
- 老师回答里出现个性化处理时，消息底部显示小 chips：`用了：怕公式 · 25 分钟`。
- 不把整张记忆表倒进每轮提示词，只选当前相关的 2–3 条。
- 记忆只在本地，不上传；可一键关闭个性化。

**验收**：
1. 修改一条记忆后，下一次同类回答能看到行为变化（例如先举例而不是先公式）；
2. 回答下方能看到“用了哪条”；
3. 删除记忆后不再使用；
4. 不同学科/课程之间不串用不相关记忆。

## 6. 页面与交互

### 6.1 无课程首页

## 7. 数据与契约

### 7.1 计划中的 schema v15

先定义三个新视图，具体字段可在实现时收敛：

```ts
type StudyProfile = {
  habits: HabitsView
  depth: StudyDepth
  personalizationEnabled: boolean
  updatedAt: string
}

type StudyUnitProgress = {
  unitOrdinal: number
  status: 'not_started' | 'learning' | 'finished'
  lastMessageId: string | null
  mastery: number
  weakPoints: string[]
  lastVisitedAt: string
}

type StudyPlanItem = {
  id: string
  kind: 'review' | 'miss' | 'continue' | 'quiz'
  title: string
  reason: string
  sessionId: string | null
  unitOrdinal: number | null
  dueAt: number | null
  done: boolean
}
```

现有 schema v14。1.0.1 需要的最小增量：

| 表/字段 | 用途 | 迁移 |
|---|---|---|
| `study_unit_progress` | 每讲状态、最后位置、掌握度、下次复习 | 从 `study_messages` / `checks` 回填 |
| `study_plan_items` | 今日计划条目、完成状态 | 新建；初次可派生 |
| `study_messages.meta_json`（或同义列） | 深度、讲法、使用过的记忆、证据状态 | 新消息写入，旧消息为空 |
| `teaching_cards` 增 `course_id` / `session_id` / `unit_ordinal` | 卡片回到课程 | 旧行可空 |
| `teaching_misses` 增 `course_id` / `session_id` / `unit_ordinal` / `source_kind` / `quote` | 错题回到课程和页 | 旧行可空，只读保留 |

迁移原则：

- 先备份 `library.sqlite`，再迁移；
- 旧数据不丢，不强行补造课程关联；
- 新写入必须带课程/讲/页；
- 迁移可重入，失败不把库留在半迁移状态。

### 7.2 契约

```ts
// 学习详情新增
type StudySessionDetail = {
  // ...现有字段
  profile: StudyProfile
  unitProgress: StudyUnitProgress[]
  plan: StudyPlanItem[]
}

// 发送时带讲解策略
type StudySendBody = {
  sessionId: string
  unitOrdinal?: number
  text: string
  mode?: StudyMode
  depth?: StudyDepth
  move?: StudyMove
}

// 题测批改结果必须能写错题
type StudyQuizGradeResult = {
  graded: boolean
  feedback: string
  gaps: string[]
  addedMisses: MissItem[]
}
```

新增/调整 IPC：

- `study.detail`：返回 `profile / unitProgress / plan`；
- `study.send`：接受 `depth / move`，只影响本轮，不改变全局默认；
- `study.plan`：返回今日计划，可由 `due`、`misses`、`summary.next` 派生；
- `study.quizGrade`：写错题，返回新增/更新的 `MissItem`；
- `teaching.misses({ courseId?, sessionId? })`：支持按课程过滤；
- `study.openOriginal`：只允许打开已导入的原文，路径由主进程解析，渲染进程不传任意路径。

### 7.3 一套账本，两个入口

复习页和右栏都只查同一份学习账本：

```text
StudyMiss / TeachingCard
        ↑
StudyService.quizGrade、check、teachback
        ↓
右栏今日计划 / 复习页 / 错题本
```

不再出现“右栏说 0 道错题、复习页说 2 道”的两套数字。

## 8. 提示词与缓存

### 8.1 稳定前缀

每轮都变化的内容不能塞进系统前缀。建议：

**稳定前缀**（同一讲内不变，利于缓存）：

- 老师人格与边界；
- 学员画像摘要；
- 课程总览、讲目录；
- 当前讲 `StudyUnit`、`keyPoints`、页摘要 `StudySlideBrief`；
- 相关记忆 2–3 条。

**每轮追加**：

- 最近 6–12 条消息；
- 本轮深度/讲法；
- 当前页引用；
- 用户这一句。

不要把“今天计划”全文、时间戳、随机 ID 放进稳定前缀；计划放在用户/系统消息的尾部。

### 8.2 讲解规则

系统提示词必须写死以下约束：

1. 一次只讲一个概念；一段只放一个意思。
2. 先定位当前页，再白话解释，再例子，再一个检查问题。
3. 事实优先引用 `[p.X]`；没有原文依据时写“我的归纳”，不编页码。
4. 按 `depth` 控制长度，按 `move` 选讲法；学生说“听不懂/太慢”时立刻换档。
5. 不一次给三个问题；一次只问一个。
6. 不把整页内容倒出来；挑 1–2 个最关键的点。
7. 讲完一讲，给总结、薄弱点、下一步；不自动布置过量作业。
8. 记忆只在相关时使用，并在消息 meta 里记录 `usedMemoryIds`。

### 8.3 成本

- 细讲/标准/速通对应不同的输出预算；
- 一讲内复用前缀缓存，切讲才重建；
- 今日计划、进度、错题统计本地计算，不额外调用模型；
- 右栏继续显示调用数、命中/未命中、输出 token，不让“个性化”变成黑盒成本。

## 10. 分期与风险

### 10.1 建议分四刀

| 刀 | 内容 | 目的 |
|---|---|---|
| P0 | schema v15、统一学习账本、今日计划派生 | 先让数据不撒谎 |
| P1 | 首屏课程状态、页证据条、右栏今日计划 | 用户第一眼看到“老师” |
| P2 | 深度/讲法切换、讲末总结、记忆可见 | 让“个性化”可感知 |
| P3 | 高 DPI 预览、打开原文件、降级提示 | 不争清晰度，但补证据体验 |

### 10.2 风险

| 风险 | 处理 |
|---|---|
| 提示词变长、缓存命中下降 | 稳定前缀 + 每讲复用；计划/进度本地算 |
| 页证据提取不准 | 没有引用就标“归纳”；对不上标“定位到页”；不伪造 bbox |
| 旧 teaching 与新 study 两套账本 | 统一到一套 miss/card；旧数据只读兼容 |
| 迁移损坏 | 迁移前备份、可重入、失败回滚 |
| 个性化变成“偷窥感” | 记忆可见、可改、可删；只注入相关 2–3 条 |
| 右栏重新变成按钮墙 | 今日计划优先，五动作收进“更多” |
| 首页改动过大被用户反感 | 保留对话为主，只加一条状态条，不做仪表盘 |

### 10.3 待拍板的默认值

设计上建议先按以下默认实现，后续再让用户改：

- 深度默认 `standard`，用户切换后记住最后一次；
- 今日计划先派生，完成状态再持久化；
- 旧 teaching 错题只读保留，不强行迁移；
- 预览优先 PDF/高 DPI，不打包 LibreOffice；
- 讲末总结默认自动生成一次，用户可手动重跑。

## 11. 一句话收尾

**豆包赢在“读文件”，灯下要赢在“把文件变成一门课上下去”。**

1.0.1 不是把界面做得更像豆包，而是把课程状态、页证据、讲解深度、错题闭环和“她记得你”放到用户第一眼能看到、第一周就能用上的地方。
