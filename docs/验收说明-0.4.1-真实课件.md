# 案头 0.4.1 真实课件验收（DeepSeek 官方接口）

0.4.0 的离线验收全部通过后，这一版做的是**真实接口 + 真实课件**的验收。用的材料是三份真实课件，
不是构造夹具：

| 课件 | 格式 | 规模 | 特点 |
|---|---|---|---|
| `数据库/ch56.pptx` | PPTX | 18 页 | 6 张表格、1 份演讲者备注、2 页含图 |
| `个人作业-法律论证标注系统.docx` | DOCX | 103 段 | 3 张用例描述表、1 张内嵌用例图 |
| `计基2/06-存储器-半导体存储器及寻址.pdf` | PDF | 82 页（4 MB） | 24 页含图表/截图，macOS Quartz 导出 |

模型：DeepSeek 官方 `deepseek-flash`（V4.1-Flash，文本 + 图片输入，1M 上下文）。
整轮验收（含一次失败重跑与两份课件的第二次重跑）共消耗 **¥3.52**（余额 27.85 → 24.33）。

## 一、解析完整性实测（真机，不走测试夹具）

| 项目 | 实测结果 |
|---|---|
| PPTX 表格 | 6 张表全部进正文，按行列取，单元格用 ` \| ` 分隔（如 `T1 \| T2`、`Slock B \| `） |
| PPTX 备注 | 全库唯一一份备注只有页码占位符（`1`），解析器正确读入且不把缩略图/页码当正文 |
| DOCX 表格 | 3 张用例表整块进正文（ID/名称/优先级/参与者及目标/主流程…），不再是 98 个散段落 |
| DOCX 内嵌图 | 1 张用例图取出为独立块，送视觉模型按块读图并缓存 |
| PDF 文字层 | 82 页全部抽出文字（197 个 page_text 块），非扫描件 |
| PDF 图片页 | 24 页含图：20 页视觉读图成功，4 页视觉失败自动退 Windows OCR，全部有结果 |
| 空页 | 末尾 1 个空白页如实报「没有可用的内容」，不编内容 |

## 二、真实模型全链路实测

三份课件各自完整跑：导入（零点击）→ 自动读懂（文字页 + 读图）→ 拆课 → 「停一下」作答 → 两轮追问 → 学习总结。

| 课件 | 用时 | 讲数 | 总览 | 两轮追问 | 总结 |
|---|---|---|---|---|---|
| ch56.pptx | ~70 秒 | 6 讲 | 228 字，点明「结果等价而非过程相同」 | 均能引用原文页码回答，第二轮引用第 3 讲反例 | 4 组，作答无关时如实写进 weak |
| 法律论证 docx | ~60 秒 | 3 讲 | 248 字，点名 3 个用例（表内容进了总览） | 第二轮引用 UC-01 扩展流程 4a | 4 组 |
| 82 页 PDF | 3 分 31 秒 | 12 讲 | 231 字，从不可能三角讲到 DRAM 寻址 | 引用第 6 页原句回答 | 3 组 |

## 三、讲稿引用逐字命中率（0.4.1 新增「原文接地」）

讲稿里的 `source` 应该是课件原文的逐字引用。用 `scripts/check-source-fidelity.mjs` 对数据库实测：

| 课件 | 命中率 | 未命中的性质 |
|---|---|---|
| DOCX | **21/21（100%）** | — |
| PPTX | **23/25（92%）** | 2 条是调度的符号序列（`Sc1=r1(A)w1(A)…`），模型抄写时丢了换行 |
| PDF | **43/48（90%）** | 5 条是表格列/公式行的压缩转述（如「按存储元件 半导体 磁表面 光介质」），全部在课程警告里标为模型转述 |

接地机制（`src/study/ground.ts`）：模型把两句原文拼成一句时，自动收回到能逐字对上的最长前缀；
一句都对不上时保留讲解、计数并写入课程警告「请对照原件」，不假装是原文。

## 四、这次发现并修掉的真实缺陷

1. **DOCX 表格整块丢失**（解析层）：表格被拆成孤立段落、表结构消失。修复：按文档顺序收块，
   `w:tbl` 整块按行列抽取，单元格段落不再散落。真实讲义从 98 个碎段变成 19 个块、3 张表完整。
2. **82 页 PDF 拆课报「模型返回的课程设计不是 JSON 格式」**（用户实际撞到）：拆课 JSON 按讲数 × 讲稿
   轻松超过 8000 token 输出上限，被截断成非法 JSON，重试也失败。修复：拆课输出上限提到 24000、
   客户端超时 120 秒提到 300 秒，重试提示要求 12 讲以内、保证 JSON 闭合。复测 3 分 31 秒通过。
3. **长课件等待无反馈**：82 页课件读懂要几分钟，界面只有一句静态文案。修复：新增
   `study.progress` 事件，三个阶段都有计数（读图 x/y 页 → 已读 x/y 段 → 正在拆课），冒烟日志实测
   「正在读懂课件里的图片页：已完成 5/6 页」逐条出现。
4. **分块理解串行慢**：改为 3 路并行，结果按原顺序落回（有测试保证顺序）。
5. **跨讲追问上下文不足**：追问提示词只带当前讲，问别的讲会答不上。修复：把全课每讲要点压成
   2600 字以内的索引随每次追问发送。
6. **分段理解的「原文摘录」**：分段理解结果新增 `quotes[]`（逐字抄原文 4–12 句），拆课要求
   讲稿引用只能从摘录里选，从源头减少长课件的转述。

## 六、仍未验证 / 已知边界

1. Windows 安装包本轮未重打（NSIS），开发模式与 `npm run build` 产物已验证。
2. `deepseek-v4-pro` 未实测（纯文本模型，读图会退 OCR）。
3. 视觉读图失败的 4 页只看到退到 OCR 成功，失败原因（图片大小/接口限制）未逐页取证；
   结果上无内容丢失。
4. PPTX/DOCX 在无 LibreOffice 沙箱证据时标「部分完成」是刻意的安全门（Office→PDF 转换未启用），
   文字与表格解析不受影响；这不是解析失败。

## 七、复验方法

```bash
# 1) 配置密钥（应用内「模型」或直接写 settings.json）
# 2) 真机冒烟（三份真实课件各自一次）
DESK_SMOKE_SHOT=docs/teaching-evidence/live.png DESK_SMOKE_IMPORT=<课件路径> DESK_SMOKE_ACTION=study \
  npx electron . --user-data-dir=<干净目录>
# 3) 数据核对
node scripts/check-source-fidelity.mjs <目录>/library/library.sqlite
```
